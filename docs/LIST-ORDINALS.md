# 영웅 목록 HOW 순번

## 정책

현재 조회 조건으로 계산된 영웅에 기존 역할 필터와 기존 정렬 비교 함수를 적용한다. 이 전체 목록의 1부터 시작하는 위치를 별도 Map으로 만든 후 검색·즐겨찾기를 적용한다. 따라서 검색이나 즐겨찾기는 순번을 다시 매기지 않는다. 역할·정렬·조회 조건이 바뀌면 새 목록의 위치를 사용한다.

Meta Score, S/A 자격, recommendationOrder, roleRank 및 통계 원본은 바꾸지 않는다. 동점 비교도 기존 이름/키 비교를 유지한다. 상태를 임시로 바꾸지 않으며 목록 선택당 enriched 계산과 정렬은 한 번만 수행한다. PC와 모바일은 같은 Map을 소비한다.

티어·Meta Score·통계 정렬에서 미분류 또는 점수 미제공 영웅은 순번 대신 `—`를 표시한다. 이들의 위치 때문에 뒤의 유효 항목 순번에 빈 번호가 있을 수 있다. 이름순의 숫자는 통계가 없어도 단순 표시 위치로 제공하며 접근성 이름과 헤더 툴팁에 ‘현재 이름 정렬의 표시 순서’라고 명시한다. 공식 오버워치 순위라고 표현하지 않는다.

## UI

PC 표에 ‘순위’ 열을 추가했다. 목표 폭은 32px이고 실제 브라우저에서 40px 이하를 검사했다. 기존 첫 열의 35% 폭 규칙이 새 열에 적용되는 충돌을 명시적 순위 셀 선택자로 해결했다. 영웅 열로 기존 너비 비중을 옮기고 2열 대시보드 전체 폭은 유지한다.

모바일은 기존 카드 헤더 안에 18px 숫자 영역을 추가한다. 별도 행·배지 없이 11px muted 숫자와 가벼운 1번 주황색만 사용한다. 초상화·4개 통계·즐겨찾기 44px 터치 영역은 유지한다.

## 검증

- 전체 테스트 220/220 통과. 기존 218개를 유지하고 모든 7개 정렬, 검색·즐겨찾기 순번 고정, 역할 변경, 지역·등급의 다른 코호트 누락 방어, 원본 불변, 미분류 및 이름 표시 순서, PC/모바일 일치 테스트를 추가했다.
- 기존 셀 인덱스 테스트는 새 순위 열만큼 이동했으며 기존 0/null/미분류 검증을 모두 유지했다.
- Chrome headless 320/375/390/430/768/1024/1440px에서 문서 가로 넘침 없음. 전체 카드 내부 넘침 없음, 표/카드 순번 일치, 모바일 검색 후 번호 고정 확인.
- 실제 저장된 통계와 API 응답 fixture로 화면을 재현했다. 새 API 통계 수집은 하지 않았다. 원본 이미지 로딩 상태에 따라 QA 스크린샷에서 기존 문자 폴백이 나타날 수 있다. 실제 모바일 기기는 미검증이다.
- 첫 모바일 카드 크기(전→후): 320px에서 296×139.4→296×139.4px, 375px에서 351×139.4→351×139.4px, 390px에서 366×139.4→366×139.4px, 430px에서 406×139.4→406×139.4px. 첫 카드의 시작 좌표도 같다. 긴 이름이나 품질 안내가 있는 다른 카드의 줄바꿈은 자연스럽게 허용한다.
- build, verify:pages, diff 검사 통과. Git status로 이전 하단 배너 미커밋 작업 보존 확인. Commit/Push/PR/배포 없음.

## 파일

- `src/models/heroModel.js`: 기존 비교 함수를 유지한 sortedHeroes, 순수 buildListSelection 및 listSelection.
- `src/views/heroView.js`: 같은 순번을 표·카드에 렌더, 접근성 설명.
- `index.html`: 표의 순위 헤더.
- `src/styles/navigation.css`: 작은 순번 열·영역과 영웅 열 너비.
- `tests/heroView.test.js`: 기존 셀 검증 보존과 새 테스트 2개.
- `scripts/qa-list-ordinals.cjs`, `docs/qa/list-ordinals/`: 브라우저 재현·전후 측정·스크린샷.
