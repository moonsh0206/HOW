# Phase 3 — 수동 카운터픽과 특전 선택률 준비

후속 수정: 아래는 최초 구현 기록이다. 현재 UI는 기존 통계 요약 패널 내부의 상단 62:38 배치이며 관계는 9/54영웅, 14개 채택·1개 검토 보류로 확대했다. 최신 검토와 변경 결과는 [Phase 3 수정 보고서](PHASE3-REVISION.md)를 참고한다.

2026-11-03. Meta Score와 티어 Domain은 변경하지 않았다. 기존 라우팅·즐겨찾기·통계 API를 유지했다. 원본 prototype, 기획서와 연구 문서도 유지했다.

## 구현

상세 페이지 통계 요약 옆에 **카운터 영웅**을 표시한다. 900px 이하에서는 통계 아래로 내려온다. 최대 3명, 기존 목록 초상화/이름, HOW가 작성한 짧은 이유, 출처 링크·검토일을 표시하고 해시 상세 경로로 이동한다. 통계가 아닌 **HOW 수동 검토**로 명시하며 상대 승률·표본·신뢰도를 생성하지 않는다.

자료가 없는 영웅은 “확인된 카운터 정보가 없습니다”, 데이터 파일 검증 실패 시 오류 안내를 표시한다. 전체 영웅 명단이 아직 없으면 잘못된 이름/이미지를 만들지 않고 가능한 항목만 출력하며 명단 도착 후 재렌더링된다. 이미지 실패 시 글자 대체가 남는다.

## 입력한 4개 방향 관계

화살표는 **왼쪽 영웅이 오른쪽 영웅을 상대하기 좋은 선택**이라는 수동 의견이다. 수학적으로 역관계를 추론하거나 반대 방향 주장을 추가하지 않았다.

| 관계 | 독립 검토의 핵심 | 참고 |
|---|---|---|
| 윈스턴 → 겐지 | 근접 전기 공격으로 튕겨내기 중심 대응을 압박하는 상황. 점프 후 고립 위험도 있음 | [겐지 가이드](https://counterpickgg.com/heroes/genji), OverFast 테슬라 캐논/튕겨내기 기술 정보 |
| 토르비욘 → 겐지 | 포탑의 경로 감시와 과부하의 생존 대응. 포탑 제거 시 효과 감소 | 같은 공개 가이드, OverFast 포탑/과부하 정보 |
| 한조 → 토르비욘 | 거리와 시야를 확보해 고정 포탑을 집중 공격하는 상황 | [토르비욘 가이드](https://counterpickgg.com/heroes/torbjorn), OverFast 활/폭풍 화살·포탑 정보 |
| 키리코 → 아나 | 정화로 수면·치유 차단에 대응할 수 있으나 재사용 대기 중에는 취약 | OverFast 정화의 방울·수면총·생체 수류탄 정보 |

공식 Blizzard 영웅 페이지는 웹 도구에서 403을 반환했다. 대신 지정한 6영웅의 공개 OverFast 상세 API를 실제 호출해 기술 명세를 확인했다(모두 HTTP 200). 확인 기록은 `research/phase3/ability-review.json`이다. 이 기록은 키트 사실의 근거이며 상성 승률 통계가 아니다. 이유는 HOW가 상황·제약을 포함해 한국어로 새로 작성했다. 외부 사이트의 점수·설명문·전체 관계망을 복제하지 않았다.

UI의 겐지 `counteredBy`는 윈스턴/토르비욘, 토르비욘은 한조, 아나는 키리코다. 토르비욘의 `counters`는 겐지이며 같은 방향 관계를 반대 관점에서 조회한 결과다. 겐지와 아나의 `counters`는 검토된 관계가 없어 비어 있다. 세 칸을 맞추기 위한 추가 관계는 만들지 않았다.

## 제공처 검토

- [CounterPickGG](https://counterpickgg.com/): 공개 영웅 가이드와 능력 기반 판단을 참고했다. 전체 DB/점수를 재사용할 권리를 확인하지 못해 실행 시 외부 요청을 하거나 자료를 미러링하지 않는다.
- [Counterwatch 방법론](https://www.counterwatch.gg/methodology): 경기 승률과 카운터 지표를 구분하고, 카운터는 커뮤니티 경기의 교전 데이터로 평가한다고 설명한다. 이는 해당 제공처의 방법론이며 HOW 수동 관계에 적용한 통계가 아니다. 점수/플레이어 수/신뢰도와 전체 DB는 가져오지 않았다.
- [OverPicker hero-info](https://api.overpicker.com/hero-info): 요청한 공개 자료로 열람만 했다. 영웅 설명·역할 혼재 위험과 점수의 검증/재사용 근거 부족 때문에 구현 데이터 소스로 채택하지 않았다. 응답 DB를 저장·변환·대량 수집하지 않았다.
- [OverLooker](https://overlooker.app/stats/perks): 기록 기반 특전 통계 화면은 확인했으나 공개 API·재사용 허가·정확한 기간/패치/식별자 계약은 미확보다. 선택률 그래프는 구현하지 않았다. 자세한 항목별 결과는 [조사 문서](PERK-DATA-RESEARCH.md)에 기록했다.

## 구조와 변경 파일

- `src/data/counters.js`: 방향 관계·자체 이유·출처·수동 검토 유형·검토일·능력 자료 URL.
- `src/models/counterModel.js`: 검증과 `heroKey/counteredBy/counters` 조회 결과, 기존 영웅 key/name/portrait 조인. 중복·자기 자신·잘못된 날짜·비HTTPS·누락 이유는 거부한다.
- `src/services/counterService.js`: 로컬 데이터 제공처, 잘못된 파일의 안전한 오류 상태. 향후 제공처 교체와 UI를 분리한다.
- `src/controllers/routingController.js`: 상세 렌더링에 같은 hero key의 카운터 결과 전달. 비동기 상세 경합 방지는 기존대로 유지.
- `src/views/counterView.js`: 안전한 textContent 기반 목록·출처·빈/오류 상태.
- `src/views/heroDetailView.js`: 통계와 카운터 조합, 미제공 특전 선택률 출처 표시. 기존 기술·특전 소개/탭/즐겨찾기 유지.
- `src/models/perkSelectionModel.js`: 허가가 확인되지 않은 선택률 미제공 상태와 향후 내부 데이터 계약. 네트워크 어댑터는 미활성.
- `src/styles/detail.css`: PC 2열, 900px 이하 1열, 줄바꿈·이미지 크기·터치 링크 조정.
- `tests/counters.test.js`: 방향·역방향 조회·누락/오류·XSS·최대 3명·이미지 대체·해시 상세 이동·기존 버튼·반응형 구조·선택률 미제공 검증.
- `package.json`: 기존에 없던 `verify`를 `verify:pages`의 별칭으로 추가. 라이브러리 추가 없음.
- `docs/PERK-DATA-RESEARCH.md`, 본 문서, `docs/research/phase3/` 검토 기록.

## 검증과 미완료

- `npm.cmd test`: 60/60 통과(기존 54 + 신규 6).
- `npm.cmd run build`: 통과.
- `npm.cmd run verify`: /HOW/ 기준 자산 5개 검증 통과.
- 모바일 검증은 DOM 순서·CSS 단일 컬럼/줄바꿈 계약 확인이다. 브라우저 도구가 **No browser is available**을 반환해 390px 실제 렌더링·터치·스크린샷·가로 오버플로의 픽셀 검증은 미완료다.
- 카운터는 일부 수동 의견이며 패치별/지역별/등급별 상대 승률을 제공하지 않는다. 나머지 영웅을 자동으로 채우지 않았다.
- 특전 선택률 API·권한·매핑이 미확보이므로 실제 선택률/그래프는 미제공이다. 운영자 연락이나 외부 계정 연결을 하지 않았다.
- GitHub Push·공개 배포를 하지 않았다.
