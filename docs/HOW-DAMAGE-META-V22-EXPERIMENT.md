## 독립 효과와 중복 반영 위험

B−A(진입 제한만): 파라 S→A, 정크랫 S→A, 시메트라 A→B. 점수·점수 순위·잠정 티어는 그대로지만 최종 자격과 표시 순서가 달라진다.

C−A(가중치만): 시메트라 A→B, 캐서디 B→A, 한조 C→D, 시에라 D→C. 백분위 65/25를 55/35로 바꾼 순수 순위 효과다.

D−B(제한 위에 가중치 추가): 캐서디 B→A, 한조 C→D, 시에라 D→C.

D−C(새 가중치 위에 제한 추가): 파라 S→A, 정크랫 S→A.

D는 픽률을 점수 35%와 최종 하한에 함께 사용하므로 중복 반영 위험이 있다. 다만 두 장치의 역할은 다르다: 비중 변경은 역할 전체의 연속 상대 순위를 바꾸고, 하한은 최종 S/A 자격을 제한한다. 연속 점수와 이산 자격을 결합하는 의도와 비용을 명확히 설명해야 한다.

승률의 비중은 여전히 55%로 가장 크며 기본 S의 승률≥50%·승률 백분위≥60을 유지한다. 실제 최신 및 66개 조건에서 모든 후보의 승률 50% 미만 S는 0명이다. 추가 합성 테스트에서도 승률 49.99%·픽률 99%로 잠정 S가 돼도 최종 A로 제한된다. A에는 승률 50% 하한이 없으므로 캐서디(48.97%)의 A 진입은 허용된다. 이것이 제품 목표와 맞는지는 승인 전에 결정해야 하며 이번 실험에서 A 승률 하한을 몰래 추가하지 않았다.

### 개발에서 비교하는 방법

- 기본 `npm run dev`와 모든 프로덕션 빌드는 v2.1이다. 환경변수가 프로덕션에 들어가도 v2.2를 선택하지 않는다.
- 명시적 v2.2 미리보기: `npm run dev:meta:v22`. v2.1 비교: `npm run dev:meta:v21`. 기존 `dev:meta`의 60:27:13 실험은 그대로 보존했다.
- 내부 선택값은 개발 모드에서만 `VITE_META_EXPERIMENT=damage-v2.2-s8a8`이며 URL·localStorage로 운영 정책을 전환하지 않는다. 테스트는 `createHeroModel([], {metaPolicy:META_V22_POLICY})`로 명시적으로 선택한다.
- 영웅 통계·상세·대시보드는 같은 모델 결과를 쓴다. 화면의 기존 로컬 실험 안내와 KO/EN/JA 티어 도움말로 구분한다. 개발 상태는 `document.documentElement.dataset.metaPolicy`에서도 확인할 수 있다.
- v2.2 미리보기에서는 기존 v2.1과 전일 순위를 비교하지 않는다. 기존 rank policy guard가 정책 불일치로 비교를 차단한다. 운영 순위 스키마·수집기·원본 스냅샷은 변경하지 않는다.
- 운영 활성화는 별도 승인과 새 순위 정책 ID·파생 캐시/기준일·배포 검증이 필요하다. 이번에는 기본 정책 변경, Commit, Push, 배포를 하지 않는다.
