작업일: 2026-11-02 (Asia/Seoul)

## 실제 API 검증

공식 스키마 https://overfast-api.tekrop.fr/openapi.json 을 읽고 실제 HTTPS 요청으로 검증했습니다. 인증키 또는 별도 크롤러를 사용하지 않았습니다.

| 항목 | 결과 |
| --- | --- |
| 한국어 heroes | HTTP 200, 54개 |
| PC/경쟁전/아시아 stats | HTTP 200, 54개 |
| key ↔ hero 연결 | 54개 모두 일치, 미매칭 0 |
| 응답 필드 | hero 문자열, winrate/pickrate/banrate 숫자 |
| 승률 범위 | 41.6~55.5% |
| 픽률 범위 | 1.6~47.5% |
| 밴률 범위 | 0~50.3% |
| 이번 경쟁전 응답 누락 | 세 비율 모두 0개 |
| CORS | 두 API 모두 Access-Control-Allow-Origin: * |
| Cache-Control | heroes max-age=86400, stats max-age=3600 |
| 빠른 대전 | HTTP 200 |
| 빠른 대전 + gold 등급 | HTTP 200; 서버가 조합을 거부하지 않음. HOW에서는 의미 없는 등급 선택을 차단 |
| 잘못된 모드 invalid | HTTP 422 |

스키마는 winrate/pickrate 0~100 숫자, banrate는 숫자 또는 null로 정의합니다. 방어적으로 누락/null 비율은 미제공으로 정규화하고 숫자 문자열·범위 밖·NaN·중복 키는 오류로 처리합니다. 0을 null로 바꾸지 않습니다. 429/503을 유발하는 부하 요청은 하지 않았으며 이 상태들은 Mock으로 검증했습니다.

원본 집계 시각, 표본 수, 시즌은 응답에 없습니다. 응답 Age는 API 캐시 나이일 뿐 경기 집계 시각이 아닙니다. 화면은 HOW 조회 시각과 원본 시각 미제공을 구분합니다. CORS 검사는 비민감 예시 Origin으로 수행했으며 최종 배포 Origin의 실제 브라우저 동작은 별도 확인이 필요합니다.

## 티어 정책

동일 조회 조건 안에서 돌격/공격/지원 각각 유효한 승률을 가진 영웅만 N에 포함합니다. 누적 경계 ceil(15N/100), ceil(30N/100), ceil(50N/100), ceil(75N/100)를 순서대로 적용하고 나머지는 D입니다. 작은 그룹 1위도 항상 S입니다. 예를 들어 N=6이면 S 1위, A 2위, B 3위, C 4~5위, D 6위입니다.

표시용 소수점 반올림 전 실제 승률이 같으면 같은 순위를 받습니다. 순위는 1,1,3 방식이며 동률 전체가 같은 티어를 받으므로 실제 등급 비중은 목표 비율을 넘을 수 있습니다. 모든 영웅의 승률이 같으면 모두 S가 될 수 있습니다. 같은 승률의 목록 표시 순서는 이름/영문 키로 정합니다.

티어는 전체 연결 후 계산하므로 검색·즐겨찾기·역할 보기·정렬 변경에 영향받지 않습니다. 승률이 없으면 미분류이며 픽률/밴률만 있을 때도 티어를 부여하지 않습니다. 알려지지 않은 영웅 키는 화면에서 제외합니다. 기존 사용시간 공식과 기존 tierByPercent는 레거시 규칙으로 보존했으며 새 역할별 분류는 roleTier를 사용합니다.

## 캐시와 실패 처리

정확한 조회 조건별 세션 메모리 캐시를 최대 1시간 유지합니다. Age를 읽을 수 있으면 잔여 TTL을 사용하며 최소 재조회 간격은 60초입니다. 영웅 정보 요청과 통계 요청은 독립적입니다. 통계 실패가 영웅 탐색을 막지 않습니다.

진행 중인 동일 조건 요청은 공유합니다. 다른 조건의 느린 응답은 Controller가 무시합니다. 새 조건을 선택하면 이전 조건의 값은 표시하지 않습니다. 동일 조건의 캐시가 만료되어 갱신에 실패한 경우 이전 성공값과 원래 HOW 조회 시각을 유지하고 오래됨을 명시합니다. 성공한 빈 배열은 정상적인 데이터 없음이며 다른 조건의 값으로 보충하지 않습니다.

429/503/기타 HTTP 오류, 타임아웃, 네트워크/CORS, JSON 오류, 잘못된 데이터는 안내하며 최소 60초 및 Retry-After 대기 후 재시도합니다. 수동 확인도 캐시와 대기시간을 지킵니다. 매초 폴링하지 않습니다. 브라우저 새로고침 후 오프라인 통계 복원은 미구현입니다.

## 검증 결과와 한계

- npm test: Mock/DOM/수집 스냅샷 테스트 20개 통과.
- npm run test:live: 실제 영웅/통계 HTTPS·JSON·CORS 통합 테스트 1개 통과. 각각 54개 확인.
- npm run build: Vite 프로덕션 빌드 성공.
- 표·카드·모달에 같은 통계를 표시하는 DOM 검증에서 52.3%, 0.0%, null, S 출력 계약 확인. 이 테스트 값은 Mock 전용이며 화면 폴백으로 사용되지 않습니다.

Computer Use가 Windows의 현재 브라우저 URL을 확인하지 못해 중단되었습니다. 실제 PC·모바일 화면, 스크린샷, 시각적 오버플로 검증은 미완료입니다. DOM 검사는 브라우저 레이아웃 검증을 대체하지 않습니다.

사용자가 npm.cmd run dev로 실행해 모드/지역/등급, 검색/역할/정렬, 카드/표/상세, 네트워크 차단 후 오래된 값 안내를 확인할 수 있습니다. 캐시 만료/시간 경과 처리는 Mock 시계를 사용해 검증했습니다. 실제 사이트에서 강제로 한 시간 기다리는 검증은 수행하지 않았습니다.

이번 작업은 로컬 변경만 수행했으며 GitHub Push·공개 배포는 하지 않았습니다. 기존 원본·기획서·인계사항은 유지했습니다.
