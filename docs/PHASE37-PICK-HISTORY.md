# Phase 3.7 — 픽률 관측 이력과 모바일 카드 축소

2026-11-03. 현재 로컬 카운터 DB·모바일 인사이트 재배치를 유지했다. Meta Score v2·정렬·필터·즐겨찾기·HOT/Hidden 알고리즘과 현재 통계 API 요청은 변경하지 않았다.

## 1. 구현 기능

상세 페이지 통계/카운터 요약 바로 다음, 기술·특전 탭보다 앞에 **픽률 변화 추이**를 추가했다. 카운터의 PC 62:38 배치는 그대로다.

- 7일 / 30일 관측 범위, 비활성 시즌 비교 UI.
- 별도 라이브러리/CDN 없이 번들에 포함한 가벼운 SVG. 픽률 Y축은 0~100%, X축은 실제 관측 날짜/시각이다.
- 관측점의 마우스 클릭·키보드 Enter/Space/포커스와 터치에서 발생하는 클릭으로 날짜·정확한 픽률을 확인한다. native SVG title도 제공한다.
- 그래프 아래 관측 원본 표(수집 시각·픽률·패치)를 펼칠 수 있다. 한국 시각 표기를 명시했다.
- 0개: “아직 수집된 픽률 이력이 없습니다.”, 1개: “픽률 변화를 기록 중입니다.”와 실제 단일 관측점. 2개 이상은 존재하는 점만 표시한다.
- 로딩, 목록/파일 조회 오류, 일부 기록 실패·재시도, 잘못된 자료 경고를 처리한다.
- 7/30일·영웅·필터 변경 중 늦은 응답을 무시한다. 같은 조건의 통계 상태 변경만으로 이력 요청을 반복하지 않는다.

## 2. 조회·정규화·연결 정책

OverFast의 과거 날짜 API를 호출하지 않는다. `public/data/snapshots/index.json`에서 **플랫폼·모드·지역·등급·전장 전체가 일치하는 파일**만 선택한다. 현재 시각부터 7/30일 이내이며 미래 관측은 제외한다. 상세와 HOT은 동일한 SnapshotService 인스턴스의 목록/파일 캐시와 진행 요청을 공유한다. manifest는 10분 캐시, 파일은 세션 캐시이며 파일은 최대 8개씩 병렬로 읽는다.

파일 내부의 조건·수집 시각을 목록과 재검증하고, hero 키가 같은 실제 pickRate만 추출한다. 0은 유효값, null/누락/문자/범위 밖 값은 없는 관측이다. UTC 날짜는 달력상 잘못된 날짜도 거부한다.

- collectedAt의 실제 시간순으로 정렬한다.
- 같은 시각의 동일 비율/패치는 하나로 합친다. 같은 시각의 값/패치가 상충하면 해당 시각을 제외하고 누락 경계로 취급한다.
- 영웅 누락·잘못된 비율·조회 실패 시각은 선 연결을 끊는다. 실패 파일을 0%로 바꾸지 않는다.
- **확인된 동일 패치, 24시간 이내, 중간 누락 없음**일 때만 관측점 사이 참고선을 만든다. 다른 패치·미상 패치·긴 공백은 연결하지 않는다. 실제 현재 자료의 patch는 null이므로 점만 표시한다.
- 참고선이 있어도 관측되지 않은 날짜/시각의 값은 계산하지 않는다. 균등한 일별 점·스무딩·보간·일별/시즌별 평균을 만들지 않는다.
- 각 값은 “해당 시각에 HOW가 관측한 픽률”이다. collectedAt는 HOW 수집 요청 시각이며 그날 하루의 집계나 원본 경기 집계 시각이 아니다. API 캐시로 여러 관측값이 같을 수도 있다.

## 3. 현재 실제 기록

현재 파일 **1개**, 영웅 레코드 **54개**다.

| 파일/시각 | 조회 조건 | 패치 |
|---|---|---|
| `2026-11-02T05-36-24.500Z.json` / 한국 2026-11-02 14:36:24.500 | PC / 아시아 / 경쟁전 / 전체 등급 / 전체 전장 | 미제공 |

기본 다이아몬드 조건은 이력이 **0개**다. 전체 등급으로 바꾸면 이 파일의 해당 영웅 관측 1개를 볼 수 있다(조회 범위 안에 있는 동안). 다이아·다른 지역으로 혼용하지 않는다. 이번에는 새 수집을 실행하거나 가짜 과거 데이터를 넣지 않았다. 다중 관측·패치 구간은 명시적인 mock 테스트로 검증했으며 운영 스냅샷에 포함하지 않는다.

## 4. 시즌 및 수집 확장

시즌 UI는 비활성이다. 검증된 시즌 시작/종료일, 패치 소속, 적절한 집계 분모가 없어서 시즌별 비교·대표 픽률은 구현하지 않았다. 향후 시즌 카탈로그는 검증된 출처·기간·관측 소속을 갖춰야 하며, 단순 스냅샷 평균을 시즌 픽률로 승격하지 않는다.

기존 `collect-snapshot.js`를 재사용한다. 옵션 없는 수집은 계속 전체 등급이며 다이아 수집은 다음 명령을 **사용자가 명시적으로 실행**할 수 있다.

```powershell
npm.cmd run snapshots:collect -- --division diamond
```

허용된 필터만 요청 전에 검사하고 같은 조건의 1시간 간격 제한을 유지한다. 시점별 전체 영웅 파일 하나를 재사용한다. 스케줄/Actions 권한/원격 저장소/배포는 변경하지 않았다.

## 5. 별도 UI 개선 — 모바일 영웅 카드

600px 이하에만 적용했다. main.css의 기존 모바일 선언과 layout.css의 더 구체적인 `#heroes` 선언을 함께 정리했다. 최종 우선순위는 layout.css이며 PC 스타일은 그대로다.

| 항목 | 이전 유효 스타일 | 변경 |
|---|---|---|
| 초상화 | 72px (350px 이하 60px) | 54px (350px 이하 52px) |
| 카드 패딩 | 14px | 12px |
| 카드 간격 | 10px | 8px |
| 이름 | 17px (좁은 화면 16px) | 15px (좁은 화면 14px) |
| identity 최소 높이 | 72px | 54px |
| 통계 영역 여백/패딩 | 12px / 12px | 8px / 8px |
| 즐겨찾기 터치 영역 | 44×44px | 유지 |

단일 컬럼을 유지하고, 초상화·이름/역할·즐겨찾기 다음 줄에 티어/승률/픽률/밴률을 배치한다. 영문 키와 META 힌트도 삭제하지 않고 짧은 메타 행으로 줄바꿈 배치했다. 통계 수치의 글자 크기는 유지했다.

**실제 카드 높이 또는 한 화면의 영웅 수를 실측하지 못했다.** 위 수치는 CSS의 변경값이며 실제 높이 감소율이나 표시 개수 증가를 측정한 결과가 아니다.

- 네트워크 실패 테스트는 mock이며 실제 다중 스냅샷 수집·시즌 자료·패치 자료를 확보했다는 뜻이 아니다. 상세 정보 자체의 OverFast 요청 실패 시에는 기존 상세 오류 UI를 유지한다.
- GitHub Push·공개 배포를 하지 않았다.
