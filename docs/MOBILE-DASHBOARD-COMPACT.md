# 모바일 대시보드 UI 정리 결과

## 정렬 조사

최신 로컬 빌드에서 검색 행의 중심과 대시보드 콘텐츠 중심의 차이는 수정 전에도 320px·390px 모두 **0px**였다. 따라서 검색창이 오른쪽으로 밀리는 오류를 이 로컬 상태에서 재현했다고 단정하지 않는다. 브라우저의 기존 15px 스크롤바 예약 공간을 제외한 콘텐츠 영역을 기준으로 측정했다.

다만 모바일 제목의 우측 여백, 절대 위치 일시정지 버튼, 별도 검색 flex 행의 배치 규칙이 여러 CSS에 분산돼 있었다. 제목·설명·검색·일시정지를 명시적인 그리드 행과 열로 분리했다. 검색은 전체 콘텐츠 폭을 쓰는 독립 행이고 입력창＋버튼은 `minmax(0,1fr) auto`로 배치한다. 최종 모바일 4개 너비와 3개 언어에서 중심 오차는 0px다. PC 배치는 변경하지 않았다. 입력창은 16px 폰트를 유지하고 검색 버튼·입력창 높이는 기존 최소 터치 크기인 44px를 유지한다.

## 변경 사항

- **추가 필터:** 기존 영웅 통계용 `syncCompactMain()`을 대시보드에서 재사용했다. 767px 이하에서 지역·등급 두 필터가 먼저 나오고, 모드·전장은 네이티브 details/summary의 ‘상세 필터’로 접는다. 기존 select/콤보박스 DOM과 이벤트·값을 그대로 이동하며 새 필터를 복제하지 않는다.
- **상태·접근성:** 펼침 상태를 통계 재렌더링·메뉴 이동·화면 크기 변경 후에도 유지한다. 적용된 모드/전장은 기존 번역된 요약에 표시된다. summary에 aria-expanded/aria-controls를 연결하고, 접을 때 내부 포커스가 남으면 summary로 돌린다. PC에서는 네 필터를 원래 위치로 복원한다. 영웅 통계의 출처 안내는 원래 화면에 보존한다.
- **접힘 모션:** `::details-content`의 높이를 250ms ease-out으로 전환한다. 지원하지 않는 브라우저에서는 네이티브 즉시 펼침이 유지된다. Reduced Motion은 전환을 끈다. 실제 Chrome에서 44px→약 93px→130px의 펼침 및 약 88px→44px의 접힘 중간 높이를 확인했다.
- **TOP 카드:** 모바일 높이 176→156px. 제목·이름·수치·보조 통계의 행 간격과 최소 높이를 정리했다. 320px의 기존 2＋1 구성은 보존하고 전체 너비인 세 번째 카드만 136px로 더 압축했다. 카드 슬라이드와 숫자·이미지는 그대로다. 375/390px의 세 언어·세 지표에서 이름/수치 겹침 및 가로·세로 넘침이 없는지 측정했다.
- **주목 영웅:** 142→126px로 압축했다. 기존 초상화 자산에 좌우 및 상하 알파 그라데이션 마스크를 intersect로 합성해 왼쪽·하단 경계가 배경으로 스며들게 했다. 흐림 필터나 새 이미지는 사용하지 않는다. 모바일/태블릿에 적용하고 PC 이미지 크기·위치는 유지한다.
- **홀로그램:** 기존 가상 요소를 사용해 역할 카드는 낮은 알파의 청록 사선·다각형 라인, 주목 영웅은 앰버 라인을 추가했다. 패턴은 정적이고 pointer-events:none이며 격리된 카드 스택의 콘텐츠 뒤에 놓인다. 기존 테두리·아우라·Meta Score 모션은 보존한다. 별도 이미지·라이브러리·무거운 blur는 추가하지 않았다.
- **순위·그래프:** 모바일 제목/설명과 행의 상하 간격, 범례 여백을 줄였다. 순위 링크·티어 버튼의 44px 터치 영역, 그래프 데이터·축·조건 콤보박스·툴팁·등장 효과는 유지한다.
- **특전:** 모바일 두 카드의 패딩·아이콘·설명 줄간격과 수치 블록 간격을 줄였다. 가운데 VS와 기존 단일 비교 막대를 사용한다. 설명 더보기, 선택률·건수 및 데이터 계산은 변경하지 않았다. PC 특전 크기는 유지한다.

## 검증

- Chrome **320·375·390·430·768·1280·1440px × 한국어·영어·일본어 = 21조합 통과**. 검색 중심, 가로 넘침, 카드 콘텐츠, 필터 키보드 조작·상태 유지, 메뉴 왕복, 특전 두 카드/막대 보존을 확인했다. [측정 결과](qa/dashboard-compact/after/measurements.json).
- **375·390px × 세 언어 = 6모션 조합 통과**. 세 지표별 실제 슬라이드 시작/중간 상태, 완료 후 카드 내부 높이·폭·이름/숫자 경계, 상세 필터 열림/닫힘 중간 높이를 검사했다. 이 검사는 대기 시간을 줄이기 위해 QA에서만 5.5초 타이머를 단축했으며 앱 코드는 변경하지 않았다. [모션 결과](qa/dashboard-compact/motion/measurements.json).
- **390·1440px 회귀 브라우저 통과:** 기존 검색→결과→플레이어 상세→뒤로 가기, 언어 전환 후 검색어·그래프 조건 유지, 그래프 독립 등급·기간, 실제 차트 등장 애니메이션. [회귀 결과](qa/dashboard-compact/regression/motion/results.json).
- 전체 단위/통합 테스트 **369/369 통과**. 기존 368개를 유지하고 공통 필터의 대시보드 상태·출처·포커스·PC 복원 테스트 1개를 추가했다.
- `npm.cmd run build` 성공: 다국어 정적 진입점 663개. 역할 평균 파생 파일은 changed:false로 데이터 변경이 없다.
- `npm.cmd run verify:pages` 성공: `/HOW/`, 에셋 18개. `git diff --check` 통과.
- 브라우저의 API는 기존에 저장된 실제 응답을 재생했다. 이번 디자인 작업에서 새 통계 수집이나 운영 API 정책 변경은 하지 않았다.

## 수정 파일과 남은 사항

앱 수정은 **`src/styles/mobileRebuild.css`와 `src/views/compactMainView.js` 두 파일**이다. `tests/compactMain.test.js`, `scripts/qa-dashboard-compact.cjs`, 본 보고서와 `docs/qa/dashboard-compact/`를 추가/갱신했다.

320px에서는 긴 언어를 읽기 위해 기존 TOP 2＋1 배치를 유지한다. 긴 필터명이 줄바꿈되는 경우 높이가 조금 늘 수 있다. 실시간 내용의 길이를 고정 높이로 잘라 숨기지는 않는다. 실제 관측 날짜가 하루뿐인 그래프의 안내도 유지한다. 기존 JS 번들 크기 경고는 이번 범위에서 변경하지 않았다.

Commit·Push·배포는 수행하지 않았다.
