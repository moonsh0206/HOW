# HOW 대시보드 밀도 최적화

기존 미커밋 대시보드 작업 위에서 UI 배치만 수정했다. 4개 KPI + 중앙 2개 패널 + 하단 3개 패널, 6명 순위, 대응 영웅 2명, 전장 대표 3명과 최근 변화 표시 로직을 유지한다. Commit·Push·배포는 수행하지 않았다.

## 실측 조건

로컬 프로덕션 빌드, 실제 Chrome, deviceScaleFactor 1 / visualViewport.scale 1(100% 배율), 동일한 저장 API 응답 재생으로 비교했다. 언어는 한국어·영어·일본어다. 변경 전 CSS·View 사본도 검증 폴더에 보존했다.

‘대시보드 높이’는 `#dashboard-page`이며 상단 공통 헤더와 푸터를 제외한다. ‘추가 스크롤’은 세 분석 영역의 마지막 카드 끝까지 필요한 거리다. 푸터까지 한 화면에 넣는 것을 목표로 삼지 않았다.

## PC 결과: 한국어

| 화면 | 대시보드 높이 전 → 후 | 감소 | 하단 패널 끝까지 추가 스크롤 전 → 후 |
| --- | ---: | ---: | ---: |
| 1440×900 | 1735.33 → 917.00px | 818.33px, 약 47% | 891.33 → 89.00px |
| 1366×768 | 1735.33 → 916.14px | 819.19px | 1023.33 → 220.14px |
| 1920×1080 | 1735.33 → 917.00px | 818.33px | 711.33 → 0px |

1920×1080에서는 한국어·영어·일본어 모두 주요 9개 카드/패널이 첫 화면에 들어온다. 한국어 기준 마지막 카드 끝 Y는 989px다.

1440×900에서는 상단 4카드와 중앙 2패널 전체, 하단 3카드의 약 60%가 표시된다. 한 화면에 모두 들어간다고 주장하지 않는다. 1366×768은 글씨와 6명 표시를 유지하며 자연스러운 스크롤을 허용했다.

### 1440×900 세부 치수

| 항목 | 변경 전 | 변경 후 |
| --- | ---: | ---: |
| 공통 헤더 | 88px | 88px |
| 제목·부제 영역 | 94.98px | 35px |
| 공통 필터 바 | 106px | 64px |
| KPI 카드 | 226.97px | 112px |
| 순위 패널 | 630.80px | 377px |
| 표 자체 | 412px | 247px |
| 추이 패널, 데이터 부족 상태 | 247.48px | 377px |
| 하단 대응 / 전장 / 변화 | 420.55 / 453.98 / 117.09px | 각각 225px |
| 중앙·하단 섹션 간격 | 20px | 12px |
| KPI 카드 간격 | 16px | 12px |
| 하단 영역 시작 Y | 1337.34px | 764px |

추이 패널은 순위 패널과 같은 높이로 맞추기 위해 빈 상태에서도 377px다. 실제 SVG 플롯은 PC에서 180px로 제한해 채워진 그래프의 불필요한 높이를 줄였다. 중앙 패널의 초기 목표 280~340px보다 높지만, 6명과 13px 통계 수치의 가독성을 유지하는 쪽을 택했다. 패널 전체를 고정 높이로 자르지 않았으므로 설명을 펼치거나 긴 콘텐츠가 생기면 자연스럽게 늘어난다.

## 변경 내용

- **상단:** 제목·부제·eyebrow를 PC에서 같은 행으로 정렬. 공통 필터의 라벨을 컨트롤 옆에 배치하고 40px 높이로 통일했다. 모바일은 기존 세로 라벨과 44px 컨트롤을 유지한다.
- **KPI:** 영웅 이미지·이름과 수치를 같은 행에 배치. PC 초상화는 48→36px, 수치는 26→24px, 패딩은 18→12px. 긴 대체 선정 이유/비교 시각은 접근 가능한 details에 보존한다. 선정 기준과 수치는 바꾸지 않는다.
- **순위:** 제목과 역할 버튼을 같은 헤더에 배치. 6명을 유지하면서 행 패딩·역할/티어 표식·푸터 여백을 정돈했다. 숫자와 영웅명은 PC 13px로 기존 12px보다 또렷하게 표시한다.
- **그래프:** 제목과 기간 콤보박스를 같은 행에 배치. 축·범례를 유지하고 설명을 details로 이동했다. SVG 좌표·값·축 계산·애니메이션 코드는 수정하지 않았다. 작은 화면에서는 SVG 레이블 글씨를 보정했다.
- **하단:** 대응 대상 영웅을 제목 옆으로 이동하고, 대응 영웅과 이유를 한 행에 배치. 전장 콤보박스도 제목 옆으로 옮겼다. 전장 선정 기준과 집계 안내는 details에서 전부 확인할 수 있다. 기존 영웅·변화량은 삭제하지 않았다.
- **상태:** 설명 펼침 상태와 summary의 키보드 포커스를 재렌더링 때 복원한다. 모바일 및 coarse pointer 환경의 터치 대상은 44px를 유지한다.

일반 메타정보는 12px, 수치는 24px, 순위 수치는 13px를 사용했다. 전체 페이지 scale, 내용 잘라내기, 카드 내부 중첩 스크롤을 사용하지 않았다.

모바일은 KPI 2열, 중앙·하단은 세로 흐름을 유지한다. 긴 이름·설명은 자연스럽게 줄바꿈하며 6명 표기를 유지했다. 320/390px 실제 검사에서 콤보박스·역할 버튼·영웅 링크·설명 summary의 터치 높이가 44px 이상임을 확인했다.

## 검증

- 변경 전·후 7개 화면 크기 × 3개 언어 **21개 조합** 실측 및 스크린샷.
- 전후 영웅 키·순서, KPI 수치, 표의 승률·픽률·밴률 fingerprint 일치.
- 문서 가로 넘침 0, JavaScript 페이지 오류 0, 상위 6명 유지.
- 별도 1920/1440/390/320px에서 로딩·503·빈 응답·정상 복원·채워진 차트 검증. 패널의 가로 넘침이나 잘림 없음.
- PC 정상 높이 917px, 로딩/빈 상태 약 910px, 자세한 오류 표시 약 990px. 모바일은 데이터가 없으면 표의 빈 공간을 강제 유지하지 않고 자연스럽게 짧아진다.
- 채워진 차트는 명시적 **TEST FIXTURE CHART — NOT OPERATIONAL HISTORY**로 검사했다. 실제 관측이 추가되었다고 주장하지 않는다. PC에서 채워진 차트도 전체 높이 917px로 유지됐다. 선의 시작·중간·완료 상태도 확인했다.
- 최종 390/1440px에서 기존 영웅 통계·영웅 상세·검색→플레이어 상세·뒤로 가기·언어 변경·캐시 동작 재검사 통과.
- `npm.cmd test`: **342개 통과**, 실패·생략 0.
- `npm.cmd run build`: 성공, 663개 정적 진입 HTML.
- `npm.cmd run verify:pages`: `/HOW/` 기준 성공.
- 번역 감사: 805개 키, 문제 0.
- `git diff --check`: 통과. 기존 줄바꿈 안내 경고만 존재.

## 이번 단계의 수정 파일

- `src/styles/dashboard.css` — 대시보드에 한정한 밀도·반응형 규칙
- `src/views/metaDashboardView.js` — 동일 콘텐츠의 헤더/행 재배치, 설명 details 및 상태/포커스 보존
- `tests/metaDashboard.test.js` — 콘텐츠·펼침·포커스 보존 회귀 1개 추가
- `scripts/qa-meta-dashboard.cjs` — 전후 실측·상태 검사 확장
- 이 문서와 `docs/qa/dashboard-density/`

기존 다른 미커밋 파일은 그대로 보존했다. 이번 단계에서 모델·통계 계산·API·라우팅·번역 사전·원본 JSON·이미지·자동화를 수정하지 않았다.
