# 개별 등급 + 상위 누적 구간

검토일: 2026-11-04. 기존 미커밋 변경과 공개 스냅샷을 보존했다. 자동 수집·예약 실행·커밋·Push·배포는 수행하지 않았다.

## 구현한 선택지

기본값은 PC / 아시아 / 경쟁전 / **다이아몬드 이상** / 전체 전장이다.

| 종류 | 선택지 |
| --- | --- |
| 개별/원본 | 브론즈, 실버, 골드, 플래티넘, 에메랄드, 다이아몬드, 마스터, 그랜드마스터·챔피언, 전체 등급 |
| HOW 누적 구간 | 브론즈 이상, 실버 이상, 골드 이상, 플래티넘 이상, 에메랄드 이상, 다이아몬드 이상, 마스터 이상 |

`diamond_plus = diamond + master + grandmaster`, `master_plus = master + grandmaster`이다. grandmaster는 보존된 공식 API 스키마의 champion 포함 구간을 한 번 사용한다. champion이나 grandmaster_plus를 새 API 등급으로 만들지 않는다. `bronze_plus`는 8개 등급의 균등 평균이고, API의 `all`과 다르다.

## 요청과 계산

Service는 누적 구간을 개별 등급으로 확장한 뒤 기존 1시간 캐시, 동일 요청 공유, 오류/타임아웃/429·503 쿨다운을 재사용한다. 실제 HTTP 요청과 응답 본문 처리를 최대 3개로 제한했다. `competitive_division=diamond_plus`는 전송하지 않는다. 내부 상태·캐시 식별용 `how_division_group`도 API에 보내지 않는다.

각 영웅에 대해 구성 등급 N개의 승률·픽률·밴률을 각각 `(값의 합)/N`으로 계산한다. 지표 평균 후 운영 65:25:10 역할별 백분위와 기존 S 자격을 적용한다. 먼저 Meta Score를 평균하는 방식은 사용하지 않는다. 기존 60:27:13 로컬 실험은 별도 실행 명령에만 남아 있다.

모든 구성 등급에서 세 지표가 유효해야 한다. 실제 0은 유지하지만 null·누락·요청 실패는 0으로 대체하지 않는다. 하나라도 불완전하면 해당 영웅의 세 지표와 점수를 미분류로 두고 누락 등급을 표시한다. 모든 등급에서 해당 영웅이 빠져도 필요한 전체 등급을 누락으로 안내한다. 지역·전장·모드가 다른 응답은 결합하지 않는다.

메인과 상세에 다음 안내를 표시한다.

> 각 등급의 통계를 동일 비중으로 평균한 HOW 종합 지표입니다. 실제 경기 수를 반영한 공식 통합 통계와 다를 수 있습니다.

빠른 대전은 기존처럼 전체 등급으로 초기화한다. 메인·상세는 같은 필터와 Model을 사용하며, 기존 요청 세대 검사를 유지해 이전 필터·영웅의 응답을 무시한다. 맵 통계의 전체 전장 비교도 동일한 누적 구간을 사용한다.

## 그래프 결합 정책

파생 이력은 메모리에서만 만든다. 원본 등급별 이력을 먼저 읽고 다음 조건을 모두 확인한다.

- 플랫폼·지역·모드·전장 및 필요한 개별 등급이 정확히 일치한다.
- 동일한 **검증된 패치**와 `since-patch-start` 집계 구간이다.
- 동일 배치 식별자가 있으면 일치해야 하며, 관측 시각의 최대 차이는 기본 5분이다.
- 각 영웅의 세 지표가 모두 존재한다. 조건이 불완전한 점은 다른 등급으로 대체하지 않는다.

현재 원본에는 전체 등급 1개와 다이아몬드 1개만 있다. 마스터·그랜드마스터 기록이 없고 패치도 미확인이므로 **다이아몬드 이상의 저장 이력은 0개**다. 현재 조회가 정상 완료되면 브라우저의 실제 균등 평균 1점만 표시할 수 있으며, 영구 저장값과 구분한다. 최신 구성 조회 시각을 점의 시각으로 쓰고 최초 구성 조회 시각도 내부 observationStart에 남긴다. 원본 경기 집계 마감 시각으로 표현하지 않는다.

검증되지 않은 기록은 개별 등급의 관측 이력에서는 기존 방식대로 볼 수 있다. 그러나 서로 같은 패치 집계인지 알 수 없는 여러 등급을 역사적 누적 구간으로 조합하지 않는다. 이 정책 때문에 누적 구간의 과거 그래프는 개별 등급보다 늦게 채워질 수 있다.

## 원본 보관과 JSON v2 준비

로컬에는 v2가 아직 없었으므로 v1/v2 호환 읽기와 수동 배치 수집 경로를 추가했다. 기존 두 파일과 index는 변경하지 않았다. 합성 구간은 수집 옵션 및 원본 스냅샷 검증에서 거부한다.

v2는 한 지역·하루의 9개 원본 등급을 한 compact JSON에 저장한다. 공통 heroes 배열과 `fields = [winRate,pickRate,banRate]`를 두고, 각 등급은 같은 순서의 세 값 배열 및 독립 관측 시각, 요청 URL, 서버 Age, 패치 확인 상태를 가진다. 성공/오류/미수집과 null/0을 구분한다. 길이·영웅 키·중복·비율을 검증하고 원본 정밀도를 보존한다. 파일 내 모든 등급을 요청마다 중복 다운로드하지 않고 파일별 pending/cache를 공유한다.

```powershell
# 계획만 출력: API 호출·파일 쓰기 없음
node scripts/collect-division-batch.js

# 추후 명시적으로 수동 수집할 때만 사용
node scripts/collect-division-batch.js --region asia --apply

# 삭제 없는 보관 계획
node scripts/snapshot-retention-dry-run.js
node scripts/snapshot-retention-dry-run.js --days 7
```

이번에는 `--apply`를 실행하지 않았다. 수동 수집기는 하나의 등급 실패를 오류 상태로 기록하고 정상 등급을 보존한다. 원본 영웅 목록과 개수를 검사하며, 기존 파일과 index를 먼저 검증하고 공통 잠금·배타적 새 파일 생성·원자적 index 교체를 사용한다. 동일 지역/UTC 날짜의 v2 파일이 있으면 덮어쓰지 않고 건너뛴다. 당일 부분 실패를 재수집해 기존 파일에 병합하는 기능은 아직 없으며 향후 별도 조각 파일 또는 승인된 보완 절차가 필요하다.

새 dry-run은 일반 보관 14일을 기본으로 하고 v1, 검토 대기, 영구 태그 및 패치 이정표를 보호한다. 동일 파일에 여러 태그를 붙일 수 있어 별도 복사본을 만들지 않는다. 실제 파일 삭제 기능은 없다. 패치 전 마지막 검증 관측과 검증된 D+1/D+3/D+7의 실제 파일을 보존 후보로 제안하며, 다음 패치 적용 이후의 값을 이전 패치 후속 관측으로 선택하지 않는다. 태그 제안은 출력만 하며 manifest에 자동 기록하지 않는다. 월간 기준점은 수동 preserveTags로 보호할 수 있다.

실제 dry-run 결과: **기존 2개 유지, 정리 후보 0개, 확정 패치 태그 제안 0개**. 스케줄·원격 워크플로는 변경하지 않았다. artifact의 저장소 반영과 Pages 배포는 별도 승인 절차가 필요하다.

## 용량과 한계

현재 공개 스냅샷 JSON은 index 포함 12,858바이트다. 기본 누적 구간에서는 index와 존재하는 구성 등급 파일을 읽을 수 있지만, 일부 등급만 있으면 합성 이력으로 표시하지 않는다. v2의 해당 등급이 필요할 때는 지역·하루 파일 전체를 한 번 다운로드한다. 다운로드한 파일은 캐시에서 재사용한다.

보존된 실제 응답 9개 등급으로 계산한 compact v2 예시 크기는 약 10,961바이트다. 14일 아시아 약 153,454바이트, 3개 지역 약 460,362바이트다. 세 지역을 매일 계속 남기는 상한 예시는 1년 약 12MB, 3년 36MB, 5년 60MB다. 실제 영구분은 패치 빈도와 D+1/D+3/D+7 및 월간 태그 선택에 따라 달라지므로 확정 용량으로 제시하지 않는다. 예를 들어 월 2개 패치, 패치당 서로 다른 4일을 남기면 연간 약 3.16MB(3지역)이며 날짜 중복에 따라 감소한다.

측정 당시 node_modules/dist/.git 제외 작업 트리는 약 17.6MB, .git 디렉터리는 약 4.97MB였다. 작업 트리 정리로 Git 과거 객체가 사라지지 않는다. 장기적으로 연도별 확정 이력 묶음 또는 별도 읽기 전용 데이터 저장소를 검토할 수 있으나 이번에 도입하지 않았다.

표본 수가 없어 균등 평균은 실제 상위 등급 전체 승률이 아니다. 현재 API 응답의 정확한 패치 집계 구간도 미확인이며, 구성 원본의 캐시 시각이 다를 수 있다. 운영 원본을 조작하거나 통계적 신뢰도를 추정하지 않았다.
