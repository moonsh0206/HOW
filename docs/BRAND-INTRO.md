# 첫 진입 브랜드 인트로 구현 결과

2026-11-19. 로컬 구현·검증만 수행했다. 기존 미커밋 변경은 보존했으며 Commit·Push·배포는 하지 않았다. 같은 내용의 첨부 요청을 확인하고 마지막 첨부본을 기준으로 구현했다.

## 원본 SVG 보존과 완성 상태

- 사용자 Downloads 파일은 수정하지 않았다. `public/assets/branding/HOW_logo_animation.svg`에 원본 39,020바이트를 그대로 복사했다.
- 두 파일의 SHA-256은 `673f073a64a53c143ea01c9aa2893e996fa8f655c8d4a44ae63571132b7188f5`로 일치한다.
- `scripts/prepare-intro-logo.js`가 인트로 전용 `src/data/introLogo.js`를 생성한다. 원본의 모든 path 좌표·그라데이션 색상·필터·439:217 비율을 보존한다. GIF·동영상·비트맵 변환은 하지 않았다.
- 이동 요소에서 최상위 439×217 배경 사각형만 제거하고 오버레이가 전체 화면 배경을 담당한다. 그라데이션과 필터 정의는 유지하며 ID·참조를 일관되게 접두 처리한다.
- 원본 33개 CSS 애니메이션을 문서 내 다른 SVG에 영향을 주지 않도록 범위를 제한했다. 반복은 1회로 변경했다. 평상시 기본 스타일은 각 애니메이션의 완성 상태이며, 실제 인트로에서만 전개 클래스를 붙인다.
- 전개 2.1초 후 클래스를 제거해 완성 상태를 유지한다. 원본도 이 시점 이후에는 완성 상태를 유지하므로 디자인·순서는 바뀌지 않는다. 이동·재배치 때 내부 애니메이션은 재시작하지 않는다.

원본을 교체하는 미래 작업에서는 다음 명령으로 파생본을 다시 생성한다. 현재 작업에서는 원본 디자인을 수정하지 않았다.

```powershell
node scripts/prepare-intro-logo.js
```

## 진행 순서

| 구간 | 동작 |
|---|---|
| 0–2100ms | 중앙에서 원본 SVG 전개 |
| 2100–2400ms | 완성 상태 300ms 유지 |
| 2400–3250ms | 동일 SVG가 우측 타깃으로 이동·축소 |
| 2650–3400ms | 대시보드 opacity 0→1, translateY 20→0, 750ms |
| 3400ms | 같은 SVG를 타깃에 정착시키고 오버레이·임시 상태 정리 |

이동과 콘텐츠 등장은 `cubic-bezier(0.22,1,0.36,1)`을 사용한다. 로고 opacity는 이동 중 1을 유지한다. 배경만 별도로 사라지며 로고는 Fade-out하지 않는다.

초기 중심 좌표는 실제 viewport 너비·높이로 계산한다. 최종 타깃의 `getBoundingClientRect()`를 읽고 translate3d/scale을 계산한다. 이동 중 화면 크기·타깃 레이아웃이 바뀌면 현재 보이는 좌표에서 새 타깃으로 재계산한다. ResizeObserver와 resize/visualViewport 이벤트는 종료 시 정리한다.

## 정착 위치와 레이아웃

PC에서는 기존 제목 행의 우측 설명과 일시정지 버튼 사이를 활용한다. 타깃은 너비 120px·행 높이 32px이며 SVG 전체 캔버스는 120×약59.32px이다. 원본 캔버스의 투명 여백을 포함한 값이고, 실제 로고 그래픽은 기존 행 안에 들어온다.

모바일에서는 기존 일시정지 버튼 행의 빈 우측 공간을 활용한다. 행 높이는 기존 44px 그대로다. 새 로고 행을 추가하거나 기존 왼쪽 헤더 로고를 교체하지 않았다. SVG는 하나만 만들며 중앙 표시와 최종 표시를 동시에 중복 생성하지 않는다.

실측 한국어 예시:

| 화면 | 최종 SVG 왼쪽/위 | 제목 행 높이 | 필터 시작점 |
|---|---|---|---|
| 1440×900 | 1241 / 91.84px | 35px, 타깃을 숨겨도 동일 | 151px, 전후 동일 |
| 390×844 | 243 / 201.86px | 123px, 타깃을 숨겨도 동일 | 266px, 전후 동일 |

18개 화면·언어 조합 모두 타깃을 숨긴 상태와 비교해 제목 행 높이·필터 시작점이 동일했다. 인트로 중 헤더·필터 높이와 스크롤 위치도 유지됐다. SVG 비율 오차 검사는 브라우저의 소수 픽셀 반올림을 고려해 높이 0.1px 이내로 검사했다.

## 첫 방문·건너뛰기·실패 처리

- `sessionStorage`의 `how:brand-intro:v1` 키를 사용한다. 영웅·플레이어 즐겨찾기와 독립적이다.
- 새 세션의 루트/언어별 홈페이지 진입만 재생한다. 새로고침, 하위 경로 직접 진입, 내부 메뉴 복귀, Reduced Motion은 생략한다. 하위 경로로 시작한 세션도 이후 메뉴 이동 때 인트로를 끼워 넣지 않는다.
- 세션 저장소가 막혀 있으면 인트로를 생략하고 완성된 우측 로고와 페이지를 즉시 표시한다.
- 인트로 중 뒤쪽 header/nav/main/footer는 inert 처리하고 키보드 포커스를 건너뛰기 버튼에 둔다. Tab으로 뒤쪽 UI에 진입하지 않으며 Escape·건너뛰기로 즉시 종료할 수 있다.
- 종료 후 inert·스크롤 잠금·타이머·RAF·이벤트·관찰자·임시 스타일을 정리하고 대시보드의 접근 가능한 필터로 포커스를 옮긴다. 라우트 이탈·문서 비활성화에서는 포커스를 강제로 옮기지 않는다.
- 백그라운드 전환·언어/라우트 이동·Reduced Motion 변경은 안전하게 최종 상태로 끝낸다. RAF 진행이 누락돼도 5초 watchdog이 화면을 복원한다.
- SVG는 번들에 포함되어 로고 파일의 네트워크 응답을 기다리지 않는다. 대시보드 API는 기존대로 병렬 로딩하며, 실패·지연이 인트로 시간을 늘리지 않는다.
- 인트로에서 통계 서비스나 카드 컨트롤러를 재생성하지 않는다. 실제 캡처 응답을 사용하는 브라우저 검사에서 초기 통계 요청은 기존과 같은 조건별 6개였고 중복 URL은 없었다.

- 시작·완성·이동 중간·최종 화면과 매 프레임 좌표/opacity를 기록했다. 동일 SVG 객체 유지, 완성 상태 유지, 원본 배경 제거, 최종 비율, 제목/필터 불변, 같은 탭 새로고침·메뉴 복귀 생략을 확인했다.
- 예외 10종: 건너뛰기, Reduced Motion, 저장소 오류, 5초 API 지연, 503 실패, 이동 중 화면 크기 변경, 빠른 라우트 변경, visibilitychange, 영웅 상세 직접 진입, 검색 직접 진입 통과.
- 예외 검사는 최종 정리/ResizeObserver 보강 후 다시 통과했다. 문서 비활성화는 브라우저의 합성 visibilitychange와 단위 테스트로 확인했으며 실제 OS 탭 전환을 직접 관찰한 것으로 보고하지 않는다.
- 기존 영웅 통계·전적 검색·상세 이동·필터·언어 상태의 390px·1440px 브라우저 회귀 검사 통과.
- 브라우저의 통계는 실제 캡처 응답을 재생했다. 새로운 실시간 통계 수집 성공을 주장하지 않는다.

남은 비용은 기존 큰 JS 번들 경고다. 제공된 벡터/애니메이션을 즉시 표시하기 위해 번들에 포함했으며 최종 JS는 약618.42kB(gzip194.08kB)이다. 별도의 애니메이션 라이브러리는 추가하지 않았다.
