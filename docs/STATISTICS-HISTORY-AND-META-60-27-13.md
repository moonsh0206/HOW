# 통계 이력 검증 및 60:27:13 로컬 실험

검토일: 2026-11-04. 기존 미커밋 v3 역할 기여도 연구는 수정하지 않았다. Push, 배포, 자동 커밋 및 예약 실행은 수행하지 않았다.

## 1. 실제 저장 구조와 보존 상태

브라우저의 현재 통계 조회는 저장소의 JSON 파일을 쓰지 않는다. 화면의 조회값은 메모리 캐시를 이용하며, 영구 통계는 별도의 Node 수집 스크립트가 파일로 저장한다. 즐겨찾기의 localStorage 저장은 통계 보관과 별개다.

기존 index와 두 JSON은 변경하지 않았다.

| HOW 수집 시각(UTC) | 조건 | 영웅 수 | 패치 |
| --- | --- | --- | --- |
| 2026-11-02T05:36:24.500Z | PC / 아시아 / 경쟁전 / 전체 등급 / 전체 전장 | 54 | 미확인 |
| 2026-11-04T00:52:25.812Z | PC / 아시아 / 경쟁전 / 다이아몬드 / 전체 전장 | 54 | 미확인 |

두 기록은 등급이 달라 같은 선으로 연결하지 않는다. 각 조건에는 저장 기록이 하나뿐이다. 11월 4일 기록의 보관된 서버 Age는 2870초다. 수집 시각은 HOW 관측 시각이며 경기 집계 마감 시각이 아니다. 이번 `node scripts/collect-snapshot.js --division diamond` 실행은 `Skipped: daily-limit`으로 종료되어 새 API 조회나 파일 추가는 없었다.

## 2. 그래프 변경과 재현 결과

기존 화면은 `buildPatchTimeline()`의 검증된 패치 대표값만 사용했다. 현재 두 파일은 patch가 null이므로 제외됐고, 이 함수는 의도적으로 `segments: []`를 반환했다. 따라서 보관 파일이 있어도 패치 이력으로 표시되지 않는 원인이 있었다.

엄격한 패치 대표값 함수는 보존하고, 화면에는 별도 `buildObservationTimeline()`을 연결했다. 동일한 플랫폼·지역·모드·등급·전장의 실제 저장 관측값을 날짜순으로 표시한다. 패치 미확인 값도 관측 이력으로 남되 검증된 패치로 승격하지 않는다. 공식 근거가 검증된 패치의 적용 D+1 이후 최초 관측은 대표값으로 표시한다.

- 저장 기록은 채운 점, 브라우저 현재 조회는 테두리 점으로 구분한다. 선택 설명과 접근성 표에 날짜, 값, 저장 여부, 패치 검증 상태를 표시한다.
- 동일 시각·동일 값은 한 점으로 합친다. 서로 다른 날짜의 같은 값은 두 점으로 유지한다.
- 같은 검증 패치의 24시간 이내 관측은 실선, 그 외 유효한 연속 관측의 비교는 점선이다. 점선 옆에 원본 집계 기간이 다를 수 있고 중간 날짜 값을 제공하지 않는다고 표시한다.
- 누락 영웅·잘못된 값·충돌 기록을 넘어 연결하지 않는다. null을 0으로 바꾸지 않는다.
- 브라우저 현재값은 원래 fetchedAt, cache/stale 정보를 유지하며 같은 조건일 때만 결합한다. 원본 파일에는 저장하지 않는다.
- 지표 전환은 이미 읽은 이력을 재사용한다. 기존 요청 세대 검사로 이전 영웅·필터의 늦은 응답이 새 화면을 덮어쓰지 않는다.

별도 테스트 fixture는 공개 데이터 폴더에 넣지 않았다. 11월 1일→2일의 테스트용 겐지 값은 승률 50→52, 픽률 10→12, 밴률 1→3이다. 각 지표에서 SVG 관측점 2개, 비교선 1개와 정확한 날짜·값을 DOM으로 확인했다. 같은 값 두 날짜도 두 점을 유지했다. 혼합 등급·지역·전장 제외, 영웅 누락, 검증 패치 둘, 현재값 중복 제거, 오류 및 라우팅 회귀도 통과했다. 실제 파일의 단일 기록과 현재 조회를 합치는 통합 테스트에서도 저장 점 1개와 미저장 현재 점 1개를 확인했다.

## 3. 수집 안전성과 향후 일일 운영

일반 수집기는 같은 조건의 최근 관측 뒤 24시간을 제한한다. 따라서 패치 전환 직전 관측이 있으면 필요한 추가 관측이 지연될 수 있었다. `--event <patchCatalog의 실제 ID>`를 명시하면 해당 조건·이벤트당 한 번 추가 관측을 허용한다. 이것은 관측 사유일 뿐 패치 검증 증거가 아니다. 새 기록도 증거가 없으면 patch와 검증 상태를 미확인으로 둔다. 기존 전용 패치 수집기의 중복 검사는 패치별이므로 다른 패치 기록이 새 패치의 첫 수집을 막지 않는다.

두 수집기는 같은 잠금을 사용한다. 기존 index와 파일 정합성을 먼저 검사하고 새 파일은 배타적으로 생성하며 index는 임시 파일을 거쳐 교체한다. 실패 시 이번 실행이 만든 파일만 정리한다. 기존 스냅샷은 보존한다. 프로세스 강제 종료로 잠금이 남으면 실행 중인 수집기가 없는지 확인한 뒤 운영자가 잠금을 정리해야 한다.

제안 운영은 매일 09:15 KST에 `node scripts/collect-snapshot.js --division diamond`를 실행하는 것이다. 실제 실행 지연에 따라 24시간 제한으로 건너뛸 수 있으므로 엄격한 달력일 1회가 필요하면 별도 날짜 슬롯 정책을 검토해야 한다. 패치 적용일과 집계 반영 증거는 별도로 확인한다. 패치 후 첫 관측은 안정된 메타를 뜻하지 않는다.

`daily-snapshots.yml`은 수동 실행만 정의했다. cron은 주석일 뿐 활성화되지 않았다. 기존 patch 워크플로도 수동 전용이다. 두 워크플로는 contents:read와 동일한 동시 실행 그룹을 사용하고, 성공·실패 시 아티팩트를 30일 보관한다. 아티팩트는 저장소 영구 보관이나 Pages 반영이 아니다. 실제 원격 Actions 실행 이력은 이번에 검증하지 않았다.

자동 운영 전 필요한 일:

1. 수동 Actions 실행과 실패 시 보존을 원격에서 검증한다.
2. 승인 후 예약 실행을 활성화하고 날짜 슬롯·API 제한 정책을 확정한다.
3. 아티팩트 검토 후 JSON/index를 저장소에 반영할 승인된 수동 또는 PR 절차를 정한다.
4. 패치 적용 시각·원본 집계 구간을 검증할 운영 절차를 유지한다. 게시 날짜만으로 검증하지 않는다.
5. Pages 반영은 별도의 승인된 배포 절차로 수행한다.

`npm.cmd run dev`로 다시 실행하면 기준 정책이다. production은 환경 변수가 남아도 기준 정책을 선택한다. 화면에 로컬 실험 모델임을 표시한다. 역할 기여도 R이나 개별 플레이어 데이터는 사용하지 않는다.

분석은 기존 2026-11-02 보존 응답 8조건·432조합에 세 모델을 각각 적용한 1296행이다. 아시아 전체·골드·에메랄드·다이아몬드·마스터·그랜드마스터 및 아메리카·유럽 다이아몬드다. 조건별로 독립 계산했으며 등급을 합산하지 않았다. 오늘의 새로운 라이브 통계나 미래 성능 검증 결과가 아니다.

마스터 둠피스트는 승률 49.7%로 두 후보에서 점수상 S 구간에 들어오지만 자격 제한으로 최종 A다. 후보 둘 모두 최종 저승률 S는 0건이다. 이는 S 제한의 효과이지 낮은 승률의 모든 과대평가를 막는다는 증거는 아니다. 백분위는 작은 원시 승률 차이도 확대하며 밴률은 성능 이외 요인의 영향을 받을 수 있다. 60:27:13은 60:25:15보다 순위 변동이 작지만 더 정확하다고 단정할 근거는 없다. 로컬 비교 대상으로 유지하고 운영 채택 판단은 추가 시점 관측을 보고 해야 한다.
