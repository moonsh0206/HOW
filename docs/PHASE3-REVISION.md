# Phase 3 수정 — 동일 요약 패널과 최신 상성 검토

후속 Phase 3.5에서 역할별 데이터와 근거 스키마를 확장했다. 현재는 54명 키트 검토·50명 입력·82관계이며, 상충 관계는 삭제하지 않고 상황별 표시한다. 아래는 이전 시점 기록이고 최신 상태는 [전체 조사 보고서](COUNTER-DATA-RESEARCH.md)에 있다.

검토일 2026-11-03(KST). 최초 구현을 확장·수정했다. Meta Score v2·승률/픽률/밴률 Service·HOT/Hidden 계산·즐겨찾기·기술/특전 기능은 유지했다. 선택률은 계속 미제공이며 내부 티어 공식은 UI에 추가하지 않았다.

## 1. 이전 배치가 달랐던 이유와 수정

이전에는 `#detail-page-statistics > .detail-overview` 아래에 `.detail-summary`와 `.counter-panel`을 형제 패널로 만들었다. 따라서 단일 통계 컨테이너 내부의 상단 배치가 아니었고, 큰 세로 목록과 별도 테두리로 독립 섹션처럼 보였다.

현재 DOM:

```text
#detail-page-statistics
└─ .detail-summary (기존 단일 패널)
   ├─ .detail-summary-top
   │  ├─ .detail-metrics (티어/승률/픽률/밴률)
   │  └─ .counter-panel
   │     ├─ 카운터 영웅 / 5v5 수동 검토·등급별 통계 아님
   │     └─ .counter-list (최대 3칸)
   │        └─ 초상화·이름 상세 링크 + 접힌 “이유”
   ├─ Meta Score
   ├─ 즐겨찾기
   └─ 조회 조건·출처·조회 시각·목록 링크
```

PC 상단은 `1.65fr : 1fr`(약 62:38), 카운터 목록은 항상 3개 열이다. 700px 이하에서는 상단만 1열로 바뀌어 통계 다음 카운터가 나오고 카운터 아이콘 3열은 유지된다. 초상화는 PC 48px/모바일 44px다. 이유·유형·날짜·출처는 각 칸의 접힌 details에 넣어 기본 높이를 줄였다. 검토된 상대가 적으면 있는 수만 보여주고 가짜 칸을 채우지 않는다.

## 2. 관계 방향과 데이터 구분

원본 관계의 `heroKey`는 현재 영웅, `counterHeroKey`는 **현재 영웅을 카운터하는 적 영웅**이다. `relationType='counteredBy'`만 허용한다. `counters`는 동일한 방향 관계를 반대 관점으로 조회하는 인덱스이며 반대 방향의 새로운 상성 주장이 아니다. 시너지는 입력/출력하지 않으며 해당 유형은 검증에서 거부한다.

추가 메타데이터:

- `gameMode='5v5'`, `reviewedAt='2026-11-03'`
- `sourceType='manual-review'`, `engagementType=direct/team-utility/team-pressure`
- `status=reviewed/needs-review`, 상충 출처의 요약 `conflicts`
- `applicablePatch=null`: 특정 패치에 대한 정량적 상성 검증이 없으므로 식별자를 만들어 넣지 않음

`needs-review`와 5v5 외 자료는 기본 조회에서 제외한다. 상충 내용을 가진 행을 reviewed로 표시하는 것도 거부한다. 원본과 UI 조인 결과의 대상 혼동을 막기 위해 원래 대상은 `targetHeroKey`로 보존한다.

## 3. 최신 공식 자료 및 패치 확인

웹 도구의 공식 페이지 접근은 403이었지만, 일반 HTTPS GET으로 [패치 노트](https://overwatch.blizzard.com/en-us/news/patch-notes/)와 [공식 영웅 페이지](https://overwatch.blizzard.com/en-us/heroes/) 및 관련 영웅 기술 페이지를 HTTP 200으로 읽었다. 응답 시각/확인한 제목은 `research/phase3/live-review.json`에 보존했다. 대량 본문 복사 대신 URL·상태·제목 기록과 자체 요약을 남겼다.

조회 시 노출된 최근 노트는 2026-10-20, 10-13, 10-06이었다. **11월 신규 패치가 존재하지 않는다고 단정하는 것이 아니라, 이번 공개 페이지에서 확인한 범위**다.

- 10-06: 겐지 질풍참/용검 조정, 아나 Minor 특전 변경, 로드호그 재설계와 압축기 추가. 기본 상성과 특전/재사용 대기 상황을 구분했다.
- 10-13: 로드호그 무기/자가 회복 조정, 키리코 기본 생명력 조정. 단순 과거 체력 수치에 의존한 상성 이유를 사용하지 않았다.
- 10-20: 표시된 항목은 일반 버그 수정이었다. 이 문서만으로 모든 기술의 과거 변경 이력을 완전히 감사했다고 주장하지 않는다.
- 공식 로드호그 기술에 투사체 흡수와 자가 회복이 함께 존재함을 확인했다. 새 아나 대응 이유에는 흡수를 피한 적중이 전제라고 명시했다.
- 공식 영웅 페이지의 기본 Abilities와 Stadium Powers를 구분했다. 6v6/Stadium 효과를 5v5 기본 기술로 가져오지 않았다.

전체 HOW 목록은 실제 OverFast 한국어 영웅 API로 재조회한 54명을 기준으로 했다. `hero-roster.json`에 키/이름/역할을 보존했다. 공식 목록은 열람했으나 단순 정적 링크 파서로는 개별 링크가 추출되지 않아 공식 명단과 1:1 키 일치를 완전히 자동 검증했다고 주장하지 않는다.

## 4. 유지·수정·보류

| 기존 관계(공격자 → 현재 영웅) | 결정 | 확인과 구분 |
|---|---|---|
| 윈스턴 → 겐지 | 유지·설명 갱신 | [Counterwatch 겐지](https://www.counterwatch.gg/stats/overwatch/counters/genji), [상성 가이드](https://counterpickgg.com/heroes/genji), 공식 전기 공격/기동 정보. 직접 교전 의견 |
| 토르비욘 → 겐지 | **검토 보류·UI 제외** | 가이드는 포탑/생존 기반 억제를 설명하지만 Counterwatch의 같은 방향 교전 지표는 이를 지지하지 않음. 서로 다른 측정 방식이며 임의로 승자를 정하지 않음 |
| 한조 → 토르비욘 | 유지·설명 갱신 | [Counterwatch 토르비욘](https://www.counterwatch.gg/stats/overwatch/counters/torbjorn)와 [상성 가이드](https://counterpickgg.com/heroes/torbjorn), 공식 활/포탑 정보. 안전한 거리·사선이 전제 |
| 키리코 → 아나 | 유지·팀 유틸리티로 명시 | [Counterwatch 아나](https://www.counterwatch.gg/stats/overwatch/counters/ana), 공식 정화/부정 효과 기술. 아군으로 아나와 함께 쓰는 시너지가 아니라 적 아나의 기술을 무력화하는 의견 |

이전 데이터는 완전히 삭제하지 않았다. 상충하는 토르비욘→겐지는 원래 설명과 두 출처의 검토 사유를 데이터에 남겼다. 외부 순위를 HOW의 정답으로 채택하거나 반대 방향의 겐지→토르비욘을 자동 생성하지 않았다.

Counterwatch 공개 페이지는 기본 5v5·전체 등급이며 2026-11-02 갱신이라고 표시했다. 해당 지표는 상대 경기 승률이 아닌 교전/팀 교전 기반 지표다. **그 수치·신뢰도·순위·전체 DB를 HOW에 복제하지 않았고 다이아몬드 전용 통계로 표시하지 않는다.** 상충 검토와 소수 관계 참고에만 사용했다.

해당 공개 화면의 집계가 경쟁전 큐만 포함하는지도 확인하지 못했다. HOW가 제공하는 것은 현재 공개된 기본 기술을 바탕으로 5v5 경쟁전에서도 검토 가능한 전술 의견이며, 최신 경쟁전의 상대 승률 검증이나 모든 조합에서의 우위를 보증하는 데이터가 아니다.

| 현재 영웅 | 표시하는 적 카운터 | 판단 유형/주요 전제 |

이는 능력 구조를 독립 검토한 **조건부 수동 의견**이다. 직접 1대1 우위와 치유 차단·위치 압박을 구분하고, 수치나 무조건적인 승리를 보장하지 않는다. 신규 관계는 공식 기술을 1차 참고로, 지정한 세 대상은 공개 상성 자료도 대조했다. 나머지 신규 관계에 동일한 제3자 경기 검증이 존재한다고 주장하지 않는다.

구축 현황: **9 / 54영웅**, 채택 관계 **14개**, 검토 보류 **1개**, 미제공 **45영웅**. [전체 영웅별 현황](COUNTER-COVERAGE.md)에 각 영웅을 빠짐없이 기록했다. 모두에게 3명을 임의로 채우지 않았다. UI의 편집 순서는 외부 순위 복제가 아니다.

## 6. 검증과 한계

- DOM 통합 테스트에서 `.detail-summary > .detail-summary-top` 내부의 통계 4개와 카운터 패널, 최대 3명, 접힌 설명, 상세 hash 링크를 확인했다.
- 방향·시너지 거부·5v5 외 거부·상충 보류 제외·정상/누락·없는 영웅·9명 커버리지·미제공 특전·공식 비노출 테스트를 유지/강화했다.
- CSS 규칙은 PC 62:38, 700px 이하 1열, 카운터 3열 고정, 작은 화면의 44px 아이콘과 줄바꿈이다.
- 브라우저 도구가 **No browser is available**을 반환했다. **320/375/390/768/1440px의 실제 픽셀 배치·오버플로·터치와 스크린샷은 미검증**이다. DOM/CSS 계약 확인을 실제 화면 검증으로 부르지 않는다.
- `npm.cmd test`: 60/60 통과. `npm.cmd run build`: 프로덕션 빌드 통과. `npm.cmd run verify`: /HOW/ 기준 자산 5개 경로 검증 통과.
