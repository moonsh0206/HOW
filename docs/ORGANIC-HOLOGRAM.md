# 비정형 홀로그램 광원 재수정

## 적용 범위

사용자가 방금 제공한 이미지에서는 어두운 미래형 패널의 깊이·청록빛 가장자리·은은한 광원 분위기만 참고했다. 캐릭터·배지·랭크 문양·글자·장식 배치를 복제하지 않았다. 원본 이미지를 사이트 자산으로 삽입하거나 새 이미지를 생성하지 않았다.

이번 앱 수정은 `src/styles/panelEffects.css`의 홀로그램 구간과 `src/views/metaDashboardView.js`의 장식 레이어/위상 설정이다. 앞서 작업한 특전 비교 패널, 막대와 퍼센트, 기존 미커밋 변경은 유지했다. 레이아웃·카드 크기·패딩·통계·API·캐시·자동 순환 정책은 변경하지 않았다.

## 반복 패턴 제거와 새 광원

기존 48×84px 육각/다각 타일, 같은 방향으로 통과하는 직선 스캔, 카드마다 동일한 부모 밝기 주기를 제거했다. 새 홀로그램에는 반복 gradient·SVG 타일·background-position 애니메이션이 없다. 각 광원은 `background-repeat:no-repeat`로 한 번만 그린다.

기존 장식 컨테이너 안에 DOM 자식 두 개와 `::before`를 사용한다.

1. **확산광:** 치우친 중심과 길쭉한 두 radial-gradient를 겹쳤다. 약간 오른쪽 위로 이동하며 1.02~1.06배 범위에서 아주 천천히 변한다.
2. **빛의 흐름:** 가장자리가 부드러운 넓은 타원형 광대역으로 만든다. 직선 한 줄이 아니라 카드 일부에 흐릿한 곡면광이 나타나며 왼쪽 아래로 작게 움직인다.
3. **반사광:** 카드 다른 모서리에 낮은 강도의 스틸블루/따뜻한 반사광을 놓고 주로 밝기만 변화시킨다.

광원은 모두 콘텐츠 뒤에 있으며 pointer-events:none, aria-hidden이다. 장식 컨테이너의 overflow:hidden으로 카드 내부에 제한한다. gradient·mask·그림자를 매 프레임 다시 조정하지 않고 정적인 광원을 transform/opacity로 합성한다. 별도 프레임 타이머·랜덤 좌표 계산·라이브러리는 없다.

| 카드 | 확산광 A | 흐름 B | 반사광 C | 기본 위상 오프셋 |
| --- | ---: | ---: | ---: | ---: |
| 돌격 | 15초 | 23초 | 31초 | 1.1초 |
| 공격 | 16초 | 21초 | 29초 | 5.7초 |
| 지원 | 14초 | 25초 | 33초 | 10.3초 |
| 주목 영웅 | 17초 | 22초 | 30초 | 14.9초 |

각 카드의 광원 중심도 다르다. 레이어별 추가 위상을 주며, 기존 카드가 새 지표로 교체될 때는 페이지 성능 시계에 맞춘 음수 delay를 사용해 처음부터 동시에 켜지지 않도록 한다. 기존 5.5초 타이머를 사용하며 새 타이머는 추가하지 않았다.

TOP 카드는 청록·블루·스틸블루, 주목 영웅은 오렌지·앰버·따뜻한 반사광을 사용한다. 주목 카드의 광원층 강도만 조금 높이며, 배경 전체를 주황색으로 칠하지 않는다. 기존 청록/오렌지 테두리·하단 메달리온·초상화 마스크·주목 카드 아우라·Meta Score 마그마 효과는 그대로다.

기존 화면 밖 observer와 숨김 상태 처리를 세 광원 모두에 적용한다. Reduced Motion에서는 움직임을 끄고 서로 겹치는 정적 확산광을 유지한다.

## 실제 브라우저 모션

390px와 1440px에서 처음에는 기존 일시정지 버튼으로 카드 지표만 고정해 **같은 영웅 카드**를 관찰했다. 실제 시간으로 0·2.5·5·7.5·10·12·15·17.5·20초의 연속 프레임을 저장했다. 애니메이션 시간을 임의로 seek하거나 최종 화면만 보고 판단하지 않았다. 목표 촬영 시간과 실제 샘플 시각은 JSON에 기록했다.

세 광원의 계산된 transform·opacity·주기, 카드 크기와 수치를 각 시점에 기록했다. 광원은 서로 다르게 변화했고 카드 크기는 변하지 않았다. 영상 파일 대신 위 시점과 중간 시점의 연속 PNG 프레임을 제공한다.

그 뒤 자동 순환을 재개해 세 지표가 기존 순서로 바뀌는 것을 확인했다. 첫 전환까지 약 5.52초, 이후 시작 간격 약 6.05~6.08초로 **5.5초 표시＋520ms 슬라이드**를 유지했다. 카드 전체 슬라이드의 중간 opacity/transform도 확인했다. 화면 밖 정지와 Reduced Motion을 함께 검사했다. [모션 및 실제 값](qa/organic-hologram/motion/results.json).

## 성능 확인

단순 시작/끝 화면 외에 Chrome Performance/Tracing도 확인했다. 20초 캡처에는 스크린샷 자체의 비용과 기존 효과가 섞이므로, 별도로 **스크린샷 없는 동일한 2초 구간**을 네 조건으로 측정했다. 해당 조건에서만 애니메이션을 QA로 일시정지했고 앱 코드는 변경하지 않았다.

아래 수치는 시스템 전체 CPU 점유율이 아니라 **페이지 메인스레드 TaskDuration/경과 시간**이다. 짧은 headless 측정이라 기기 FPS나 모바일 배터리 보장으로 해석하지 않는다.

| 조건 | 390px 작업 비율 | 1440px 작업 비율 | 2초 Paint |
| --- | ---: | ---: | ---: |
| 전체 효과 | 16.39% | 26.75% | 각 242회 |
| 새 광원만 | 0.28% | 0.43% | 각 0회 |
| 기존 Meta Score/아우라만 | 16.17% | 20.97% | 각 242회 |
| 모두 정지 | 0.05% | 0.03% | 각 0회 |

모든 조건에서 Layout 0회, 측정 구간의 ScriptDuration 0초였다. 새 광원만 실행한 구간에는 반복 Paint가 관측되지 않았다. **전체 화면이 페인트 없이 동작한다고 보고하지 않는다.** 기존 Meta Score 배경 효과의 페인트 비용은 남아 있고, 사용자가 유지하도록 지정한 효과라 이번 범위에서는 변경하지 않았다. 두 조건의 차이를 엄밀한 전체 CPU 증가량으로 단정하지 않는다. [동일 조건 분리 측정](qa/organic-hologram/performance/results.json).

실제 저사양 휴대폰의 FPS·전력 측정은 하지 않았다. 필요하면 기존 Meta Score 효과의 성능 최적화를 별도 범위로 검토할 수 있다.
