# 모바일 메타 요약 중간 패치

2026-11-03. 모바일 메인 페이지의 View와 레이아웃만 수정했다. 기존 진행 중인 Phase 3/3.5 변경은 보존했고, 이번 작업에서 Meta Score·티어·HOT/Hidden Picks·필터·즐겨찾기·카운터 DB·상세 페이지·API는 수정하지 않았다.

## 원인

기존 main.css는 작은 화면에서 workspace/sidebar를 1열로 바꾸고, detail.css 및 layout.css도 모바일 insight-grid/classification-grid를 1열로 덮어썼다. 인사이트가 긴 영웅 목록 뒤의 sidebar에 위치한 데다, 각 카드에 역할별 영웅과 설명이 모두 펼쳐져 스크롤이 길어졌다. 컨테이너 폭만 100%로 바꿔서는 순서와 정보량이 해결되지 않는다.

## 변경

- `createInsightView()`가 **동일한 `.meta-insights` 노드 하나**를 사용한다. 600px 이하에서는 조회 필터 컨테이너 바로 다음, 역할/검색/정렬 및 영웅 목록보다 앞에 배치한다. 그보다 넓으면 원래 사이드바 위치로 되돌린다. resize로 API를 호출하거나 Model 상태를 변경하지 않는다.
- 모바일 HOT/숨은 꿀영웅은 **2열 미니 카드**다. 28px 초상화, 이름, 실제 핵심 지표만 먼저 보여준다.
- 승률/픽률/밴률은 **3열 소형 카드**다. 기존 Domain이 선정한 역할별 대표 3명 중 해당 지표가 가장 높은 한 명을 View에서 먼저 보여준다. 도메인 후보 선정이나 수식 변경이 아닌 표현 순서다. 전체 역할별 대표는 “상세”에서 확인한다.
- 추가 영웅·설명·추세 비교 시각은 모바일에서 접힌 details로 제공한다. 터치 영역은 최소 44px이며 펼침 상태는 통계 재렌더링에도 유지된다.
- 실제 데이터나 비교 가능한 과거 통계가 없으면 기본 카드에 **미제공**, 상세에는 원인을 표시한다. 이전 수치를 현재 값처럼 대체하거나 상승률을 만들지 않는다.
- 이름/수치는 줄바꿈하며 자르거나 줄임표로 숨기지 않는다. 좁은 그리드에 minmax(0,1fr), min-width:0와 제한된 이미지 크기를 사용한다. 핵심 수치는 11px, 이름은 12px다.
- PC에서는 기존 사이드바·카드 그리드·영웅 출력 순서·문구를 유지하고 상세 내용을 전부 펼쳐 표시한다. 601px 이상에는 새 토글을 보이지 않게 한다. 기존 PC 스타일을 재설계하지 않았다.

현재 화면 순서는 제목/조회 요약·즐겨찾기·지역/등급 필터 → 모바일 메타 요약(2열+3열) → 역할/검색/정렬 → 영웅 카드다. 인사이트를 복제하지 않아 중복 HTML ID나 별도 모바일 통계 상태가 없다.

## 검증

- `npm.cmd test`: **65/65 통과**(기존 62 + 신규 View 회귀 3).
- 320/375/390/430/600px 조건에서는 필터 다음으로 이동, 768/1440px에서는 원래 사이드바로 복원됨을 **matchMedia를 모사한 DOM 테스트**로 확인했다. 모든 전환에서 동일 노드·중복 ID 없음·원본 통계 불변을 확인했다.
- 기존 실제 API 증거를 이용해 모바일 대표 지표와 PC 전체 대표 목록의 데이터 일치, 대표 영웅 링크·PC 순서 복원을 확인했다.
- 별도로 명시한 mock history 테스트에서 HOT의 수치·링크가 화면 전환으로 변하지 않는지 확인했다. mock은 테스트에만 존재하며 운영 화면의 통계 대체값으로 쓰지 않는다.
- 데이터 로딩/오류/과거 기록 부재, 미제공 표시, 상세 펼침 유지도 검증했다.
- `npm.cmd run build`: 프로덕션 빌드 통과.
- `npm.cmd run verify`: 카운터 DB 검증과 /HOW/ 기준 자산 5개 경로 검증 통과.
- 브라우저 도구는 **No browser is available**을 반환했다. 위 7개 폭에서 **실제 픽셀 배치·카드 높이·글자 잘림·가로 넘침·터치 편의성·스크린샷은 미검증**이다. DOM/CSS 검증을 실제 화면 검증으로 간주하지 않는다.
