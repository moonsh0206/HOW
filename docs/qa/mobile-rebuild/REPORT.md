# 모바일 UI 리빌드 검증

## 구현

- 사용자 제공 모바일 시안의 TOP 3 → 상태 점 → 가로형 주목 영웅 → 순위표 → 추이 → 하단 분석 흐름을 적용했다.
- 360~1199px는 TOP 3열, 320px는 긴 이름과 수치 가독성을 위해 2열＋아래 한 카드를 사용한다. 이름은 카드 폭 전체를 사용하고 초상화와 핵심 수치를 같은 행에 놓았다. TOP 카드 높이는 176px로 고정해 지표 교체 시 흔들리지 않는다.
- TOP 카드의 역할 아이콘, 기존 청록 프레임, 520ms 전체 카드 슬라이드, 전환 완료 후 5.5초 표시 시간을 유지했다. 점은 현재 지표와 동기화된다. 별도 지표 선택 버튼은 추가하지 않았다.
- 주목 영웅은 모바일에서 가로 배너로 배치했다. 기존 초상화, 실제 HOW 티어, Meta Score, 느린 아우라와 마그마 효과를 사용한다. HOT 선정 조건을 바꾸지 않았다. HOT 조건을 만족하지 않는 경우 기존 ‘HOW 티어순 선두’ 안내를 표시한다.
- 모바일 순위표는 기본 3행이며 버튼으로 기존 6행을 모두 볼 수 있다. 언어 갱신 시 펼침 상태도 유지한다. PC는 기존 6행과 4＋2＋3 구조를 유지한다.
- 맵별 주요 영웅·최근 변화는 모바일 2열이며 상대 영웅 대응은 별도 전체 너비 패널로 보존했다.
- 영웅 목록 공백 원인은 `metaEmblems.css`의 모든 통계 dd에 적용된 66px 최소 높이와 18px 하단 패딩이었다. 모바일에서 해당 고정 공간을 제거하고, 조건부 추천 문구가 있을 때만 필요한 공간을 남겼다. 카드 높이 제한이나 콘텐츠 잘라내기는 사용하지 않았다.
- 특전은 단계별 두 카드와 한 비교 막대로 변경했다. 첫 카드는 블루, 둘째는 오렌지이며 원형 아이콘과 선택 건수를 유지한다. 선택률은 표시 시 소수점 한 자리로만 반올림한다.

## 특전 데이터 기준

OverLooker의 동일 heroKey·단계·queue_type·since 및 검증된 perkKey에 속한 두 항목만 비교한다. 저장된 선택률과 선택 건수를 그대로 사용하며, 선택 건수를 분모로 새 비율을 만들지 않는다. 합계가 100% 미만이면 남는 부분을 중립색으로 두고 안내한다. 합계가 100%를 초과하거나 항목이 누락되면 단일 비교 막대를 표시하지 않는다. 원본 파일과 API 요청 구조는 변경하지 않았다.

54명·216개 특전·108개 단계 조합을 저장된 실제 원본으로 검사했다. 기존 설명 더보기, 비동기 갱신, 포커스 및 출처 표시를 보존했다.

## 실제 Chrome 검증

`after/measurements.json`에 320×700, 360×800, 390×844, 430×932, 768×1024, 1366×768, 1440×900, 1920×1080 각각 한국어·영어·일본어 결과를 저장했다. 각 조합의 dashboard / tiers / perks PNG도 같은 폴더에 있다. 각 화면의 가로 넘침, TOP 슬롯, 특전 2열 및 단계별 비교 막대를 검사했다.

- `motion/cycle-results.json`: 1440px와 390px에서 픽률→승률→밴률→픽률의 실제 시작·중간·종료 상태, 전체 ARTICLE 슬라이드, 고정 외곽 크기, Hover·Focus 일시정지, Reduced Motion을 검사했다. 첫 전환까지 약 5.5초, 이후 전환 시작 간격 약 6.05초로 520ms 전환＋5.5초 표시 시간을 확인했다.
- `metric-layout/results.json`: 390px의 세 언어·세 지표에서 실제 영웅 이름과 수치의 경계 좌표 및 카드 내부 가로·세로 넘침을 검사했다. 최초 일본어 Jetpack Cat 이름의 9px 넘침을 발견한 뒤 이름 전체 폭 배치로 수정하고 재검증했다. 이 검사는 대기 타이머만 단축했으며 통계 데이터는 변경하지 않았다.
- `intro/results-quick.json`: PC 1440px·모바일 390px에서 중앙 전개 → 좌측 헤더 정착, 중복 로고 없음, 레이아웃 및 스킵·새로고침 동작을 검사했다. 원본 인트로 구현과 SVG는 수정하지 않았다.
- `states/results.json`: 390px·1440px의 지연 로딩, API 503, 빈 통계 및 특전 파일 실패를 재현했다. 가짜 영웅·수치·막대가 생성되지 않으며 특전 설명은 유지된다.
- `motion/results-quick.json`: 기존 지역·역할·기간·언어 필터, 영웅 상세, 플레이어 검색·상세 및 뒤로 가기 흐름을 검사했다.

브라우저 통계는 기존에 실제 API에서 저장한 응답 및 운영 원본을 재생했다. 신규 실시간 API 수집 성공으로 보고하지 않는다. 같은 흐름의 API 요청은 수정 전후 모두 9회로 추가 요청이 없다.

## 테스트 및 제한

- 전체 회귀 테스트 363/363 통과. 기존 360개를 유지하고 3개 추가했다.
- 마지막 특전 중복 텍스트 정리 후 관련 13개 테스트도 다시 통과했다.
- 프로덕션 빌드 성공, 다국어 정적 진입점 663개 생성.
- Pages 검증 성공: `/HOW/`, 로컬 에셋 17개.
- 기존 JS 번들의 500kB 초과 경고는 남아 있다. 이번 범위에서 코드 분할 구조는 변경하지 않았다.
- 최근 7일에 유효한 동일 조건 관측값이 부족한 경우 시안의 곡선이나 변화량을 임의 생성하지 않는다. 기존 안내를 유지하므로 참고 이미지와 다르게 보인다.
- 320px는 TOP 카드 3열보다 가독성을 우선했다. 하단 맵 카드는 실제 3역할 데이터와 출처를 유지해 시안의 장식용 작은 카드보다 길다.
- 인라인 참고 이미지의 수치와 영웅을 복제하지 않았으며, 특전 비교는 대시보드에 중복 추가하지 않고 영웅 상세에 적용했다.
- Commit·Push·배포·워크플로 활성화는 수행하지 않았다.
