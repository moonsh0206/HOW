## 확인한 외부 제공처 문제

OverFast 공개 main의 [hero_stats_summary.py](https://github.com/TeKrop/overfast-api/blob/main/app/domain/parsers/hero_stats_summary.py)는 원본 `-1`을 `0.0`으로 변환한다. 승률뿐 아니라 픽률·밴률에 같은 함수를 적용한다. 이 변환은 실제 0과 미제공을 구별할 정보를 잃는다. 공개 main과 운영 서버의 실행 커밋이 동일한지는 확인하지 못했다.

실제 조회 조건은 PC / 아시아 / 경쟁전 / 그랜드마스터·챔피언 / 전체 전장이다.

- OverFast 응답: 2026-11-04T12:41:21.313186Z에 HOW 감사 도구가 관측, HTTP 200, 54명, 응답 Age 1985초, X-Cache-Status hit, HTTPS, CORS Allow-Origin `*`.
- 블리자드 원본: 2026-11-04T12:41:53.620145Z에 관측, HTTP 200, 54명. 공식 페이지의 경쟁전 옵션은 rq=1, 최상위 옵션은 Grandmaster and Champion이었다. JSON의 selected도 PC/1/Asia/all-maps/Grandmaster로 일치했다.
- 공식 원본 URL은 OverFast 공개 설정과 파서가 사용하는 [rates/data](https://overwatch.blizzard.com/en-us/rates/data/?input=PC&rq=1&region=Asia&map=all-maps&tier=Grandmaster)이다. 사용자 화면에 원본 통계를 대체 연동하거나 추가 자동 요청하지 않았다.

제보의 0 승률·픽률은 재현됐다. 리퍼·마우가의 양수 승률은 제보 당시와 달랐다. 이번 응답에서는 54명 모두 세 지표 중 하나 이상이 별도 관측한 공식 원본과 달랐다. 캐시/관측 시각 및 확인되지 않은 집계 구간이 달라 **동일한 원본 JSON을 직접 변환한 결과라고 단정하지 않는다.** 캐시 차이가 모든 차이의 원인이라고 입증한 것도 아니다.

특히 현재 받은 공식 원본에는 `-1`이 하나도 없었다. 따라서 토르비욘 등의 이번 0이 바로 `-1`에서 왔다고 영웅별로 확정하지 않았다. 소스의 정보 손실은 확인했지만 이번 두 응답만으로 과거 캐시 원본의 결측 여부를 복원할 수 없다. 공식 양수 값으로 OverFast 값을 임의 교체하지 않았다.

## HOW 자체 문제와 수정

이전에는 normalizeStatistics가 null/undefined만 null로 바꾸고 0~100 숫자를 모두 유효하게 받았다. attachMetaTiers는 숫자 범위만 확인했고, 합성 등급도 숫자이면 평균했다. UI는 null이면 미제공, 0이면 0.0%로 표시했다. 따라서 외부 변환으로 의미를 잃은 0도 정상 값처럼 티어·평균·승률 이력에 사용됐다.

수정 후 품질 상태를 숫자와 분리한다.

| 상태 | 저장/정규화 값 | UI | 티어/평균 |
| --- | --- | --- | --- |
| 원본에서 확인한 -1 | null + confirmed-missing | 미제공 | 제외 |
| OverFast 승률 0, 픽률은 숫자, 원본 확인 없음 | 원값 0 + review | 0.0% · 검토 중 | 보류 |
| 직접 확인한 공식 원본의 실제 0 | 원값 0 + verified | 0.0% | 기존 정책 적용 가능 |
| 정상 밴률 0 | 원값 0 | 0.0% | 유지 |

원본 정규화는 `normalizeBlizzardStatistics()`가 selected 조건을 검증한 뒤 명시적인 Blizzard 소스로 호출한다. 이때만 -1을 null로 해석한다. OverFast에서 예상 밖 -1이 오면 기존 범위 검증 오류로 처리하며, 임의로 다른 스키마라고 가정하지 않는다. 외부 payload의 임의 quality 필드는 신뢰하지 않는다.

실제 운영 Service는 계속 OverFast를 사용한다. 이번에 확인된 영웅별 원본 결측이 없으므로 정적 영웅 예외표나 응답을 덮어쓰는 보정표는 만들지 않았다. 확인된 원본을 명시적으로 넣을 수 있는 안전한 어댑터와 미확인 값의 보류 경로를 구현한 것이다.

동일 품질 검사를 Domain과 복합 등급 Model에서 다시 사용해 정규화 우회 입력도 안전하게 처리한다. diamond_plus/master_plus 구성 중 한 등급이라도 검토/미제공이면 합성 영웅은 미분류이고 해당 등급을 안내한다. 필수 등급을 빼고 분모를 줄이지 않는다. 원본 응답의 0은 그대로 보존하며, 합성 결과의 null은 '구성 통계 불완전으로 계산하지 않음'을 뜻한다.

의심 승률은 시계열 관측점으로 그리지 않고 해당 위치에서 선을 끊는다. 유효한 픽률·밴률 이력은 유지한다. 맵별 승률 차이와 승률을 사용하는 HOT/Hidden 비교도 검토 값을 제외한다. 원래 계산식·가중치·S 자격 문턱은 변경하지 않았다.

불확실한 영웅을 역할 비교 모집단에서 제외하므로 해당 응답의 다른 영웅 점수·순위·티어는 재계산될 수 있다. 이전의 오염된 모집단 순위를 고정하지 않는다. 이상이 없는 기존 8조건·432조합은 이전 계산과 동일함을 테스트했다.

## 브라우저 일관성과 시각 정보

390/1440 너비 속성을 가진 두 독립 jsdom에 동일한 실제 응답, 영웅 목록, 필터, 정책 및 소스 코드를 넣었다. 전체 54명의 score/rank/tier가 같고, PC 테이블과 모바일 카드 모두 검토 표시와 미분류가 일치했다. 이는 DOM/계산 재현이며 실제 Chrome/Safari 등 서로 다른 브라우저 엔진 또는 실기기 시각 검증은 아니다.

같은 배포 버전과 통계 응답이어도 영웅 목록의 역할 메타데이터가 다르면 역할별 평가 결과가 달라질 수 있다. 재현에는 hero 목록도 동일해야 한다. 실제 사용자 차이는 조회 쿼리, 통계 응답 해시, 영웅 목록, 캐시·stale 여부, 실행 정책과 배포 JS 해시를 함께 비교해야 한다. 현재 빌드는 로컬에만 있으며 공개 사이트가 자동 수정된 것은 아니다.

UI는 HOW 조회 시각, 브라우저 캐시 재사용 여부, 응답 당시 API 캐시 Age를 구분하고 원본 집계 시각은 미제공으로 남긴다. 표시 시각은 아시아/서울로 통일했다. 서버 측 점검에서 읽은 Age 1985초는 경기 집계 시각이 아니다. 브라우저에서 Age 헤더가 CORS로 노출되지 않으면 미제공으로 표시한다. 복합 등급은 각 구성 등급의 시각과 Age를 상세 통계 정보에서 확인한다.

## 남은 외부 검증 과제

제공처가 결측을 null 또는 availability 필드로 보존해야 손실된 의미를 복구할 수 있다. 과거 API 캐시에 대응하는 정확한 원본 응답과 집계 기간도 필요하다. 실제 0을 입증할 원본이 없으면 검토 보류를 유지하므로 진짜 0도 일시 보류될 수 있다. 이것은 D로 강등하거나 결측으로 확정하는 것과 다른 보수적 안전장치다. 양수 통계의 제공처 간 차이는 이번 규칙만으로 해결하지 못했다. 소스 교체·확정 보정·외부 이슈 등록은 수행하지 않았다.
