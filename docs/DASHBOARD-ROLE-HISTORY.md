# 대시보드 역할별 관측 및 검색 통합

## 원인과 운영 상태

2026-11-20 로컬 조사 시 역할 평균 아카이브는 50개였고 최신 관측은 2026-11-06T02:38:31.943Z였다. 기본 최근 7일 범위에 기록이 없었다. 다이아 이상은 11월 6일 하루만 저장돼 있었으므로 30일에서도 두 날짜의 추이를 만들 수 없었다. 원본→파생 평균 계산 오류가 아니라 오래된 수집 상태와 실제 날짜 부족이 주요 원인이었다.

확인된 추가 구현 문제도 수정했다.

- 수집 CLI는 원본만 저장하고 파생 평균은 다음 빌드까지 갱신하지 않았다. 기존 적응형 수집기가 원본 저장에 성공하면 즉시 같은 `deriveRoleMeans()`를 호출하도록 연결했다.
- 파생 스크립트가 현재 원본 인덱스만으로 파일을 다시 만들므로, 원본 보존 기간이 지나면 과거 파생 평균까지 사라질 수 있었다. 동일 버전·역할 명단의 기존 평균을 병합 보존한다. 손상된 아카이브와 역할 명단 변경은 조용히 덮어쓰지 않고 명시적 마이그레이션을 요구한다.
- 서비스가 최신 관측과 집계 구간이 다른 과거 기록을 전부 제외했다. 이제 올바른 동일 조회 조건의 과거 관측은 보존하고, 서로 비교할 수 없는 구간은 선으로 연결하지 않는다.
- 실제 차트가 생긴 뒤 320px에서 접근성용 표가 화면 너비를 늘리는 문제를 발견했다. 표를 시각적으로 숨긴 래퍼 안에 두어 읽기 기능을 유지하면서 넘침을 제거했다.

공개 GitHub/Pages를 읽기 전용으로 확인했다. 워크플로 상태는 `active`였지만 최근 예약 실행 세 건의 `publish` 작업은 모두 `skipped`였다. 따라서 자동 수집 성공으로 볼 수 없다. `HOW_GRAPH_ARCHIVE_ENABLED` 변수 조회는 HTTP 401로 확인하지 못했다. 비활성 변수인지, 다른 작업 조건 때문인지는 확정하지 않았다.

- [최근 확인 실행](https://github.com/moonsh0206/HOW/actions/runs/44585831401)
- 공개 Pages의 역할 평균 파일은 여전히 50개, 최신 11월 6일이었다.
- 공개 Pages 원본 인덱스도 29개 항목, 최신 11월 6일이었다.
- 근거: [remote-audit.json](qa/dashboard-history/remote-audit.json).

## 실제 로컬 수집 결과

기존 `collect-adaptive-snapshots.js`를 아시아만 대상으로 실행했다. 기존 적응형 정책이 일반 관측을 허용했고 9개 원본 등급 모두 성공했다. 통계 API 9회와 영웅 명단 조회 1회를 사용했다. 합성 등급용 추가 API 요청은 없다. 유럽·아메리카를 불필요하게 재수집하지 않았다.

- 새 원본: `public/data/snapshots/2026-11-20T00-24-17.799Z.json`
- 최신 실제 관측: `2026-11-20T00:24:17.773Z` = **2026-11-20 09:24:17 KST**.
- 역할 평균: **50→66개**. 새 원본 9조건과 합성 7조건의 16개 평균 프레임을 생성했다.
- 기존 50개 평균은 동일 내용으로 모두 보존됐다. 기존 원본 파일을 수정하거나 삭제하지 않았다.
- [수집 결과](qa/dashboard-history/collection.json), [원본 보존 확인](qa/dashboard-history/source-integrity.json).

최근 30일의 실제 유효 관측 날짜 수는 세 역할에서 같다.

| 지역 | 등급 | 유효 날짜 |
| --- | --- | --- |
| 아시아 | 전체 등급 | 3일: 11/2, 11/6, 11/20 |
| 아시아 | 개별 다이아몬드 | 3일: 11/4, 11/6, 11/20 |
| 아시아 | 나머지 개별 등급 및 7개 합성 등급 | 2일: 11/6, 11/20 |
| 유럽·아메리카 | 지원되는 16개 등급 조건 각각 | 1일: 11/6 |

최근 7일은 아시아만 오늘 하루가 있다. 한 날짜의 값은 실제 점으로 보여주고 ‘아직 추이가 아님’을 안내한다. 30일 선택으로 과거 관측도 볼 수 있다. 수집되지 않은 날짜를 보간하거나 오래된 기록을 오늘 기록으로 바꾸지 않는다. 날짜가 연속하지 않으면 선을 끊는다. 따라서 현재 운영 원본 화면에 점선이 이어지지 않는 것은 실제 날짜 공백에 따른 정상 표시다. 연속 날짜와 서로 다른 집계 구간의 선 연결은 회귀 테스트로 검증했다.

조건별 모든 값·유효 영웅 수·날짜·연결 여부는 [availability.json](qa/dashboard-history/availability.json)에 있다.

## 집계와 패치 정책

`how-role-hero-mean-v1` / `equal-hero-weight-complete-roster` 정책을 유지했다. 돌격 15·공격 23·지원 16명의 각 영웅 승률을 동일 가중 평균한다. 결측·검토 통계는 기존 품질 정책으로 제외하며, 역할의 유효 영웅이 전체 명단보다 부족하면 평균을 null로 둔다. 역할 전체 경기 수를 가중한 공식 역할 승률이 아니다.

합성 등급은 기존 HOW의 원본 등급 균등 평균으로 만든 영웅 통계를 재사용한다. 원본과 합성 등급을 다시 섞어 평균하지 않는다. 정책 버전·명단·KST 날짜·UTC 수집 시각·조회 조건·역할별 count/targetCount·원본 파일 및 SHA·패치 검증 정보는 기존 포맷으로 보존한다. 같은 KST 날짜는 해당 조건의 마지막 유효 관측을 화면 대표로 선택하지만 이전 원본/평균 기록은 삭제하지 않는다.

현재 아카이브의 통계 반영이 검증된 패치 관측은 **0개**다. 이번 수집도 패치 미확인 일반 관측이다. 패치 카탈로그의 발표일 마커는 참고 표시이고 통계 반영을 뜻하지 않는다. 툴팁에는 실제 수집 시각과 검증된 패치 ID 또는 패치 미확인을 표시한다. 서로 다른 집계 구간·패치 검증 상태는 연결하지 않는다. 단지 오늘 수집했다는 이유로 최근 공식 패치 효과라고 표시하지 않았다.

## UI 및 검색 연결

- 그래프 전용 등급 기본값은 다이아 이상이다. 기존 `RANK_OPTIONS`와 `createFilterCombobox()`를 재사용한다. 9개 원본 조건＋7개 합성 조건을 지원하며 기록이 없는 조회는 값을 만들지 않는다. 빠른 대전은 전체 등급만 사용한다.
- 지역·플랫폼·모드·전장은 공통 조건을 따르되 등급은 그래프 내부 상태로 분리했다. 상단 카드·영웅 순위는 바꾸지 않는다. 기간·등급·조건을 요청 키에 넣고 세대 토큰으로 늦은 응답을 차단한다.
- 차트 색상은 돌격 `#55A8F6`, 공격 `#F2A448`, 지원 `#57C4A3`로 고정했다. SVG 점·점선과 기존 520ms reveal/점 fade 애니메이션을 재사용하며 Reduced Motion을 지원한다.
- 각 점을 키보드로 포커스할 수 있고 실제 값(소수점 둘째 자리), 명단 커버리지, 수집 시각, 패치 상태를 툴팁과 접근성 표로 제공한다.
- 대시보드 제목 오른쪽의 설명 공간에 검색창을 넣었다. 일시정지는 맨 오른쪽에 유지했다. 모바일은 제목 아래, 필터 위에 놓았다.
- 검색창은 기존 `playerQuery()`로 검증한 뒤 `how:playersearch` 이벤트로 명시적인 일회성 요청 상태를 전달한다. 라우터가 언어별 기존 검색 화면으로 이동하고, 기존 PlayerSearchController의 reset/search를 실행한다. 검색어를 결과 입력창에도 그대로 유지한다. API 서비스와 캐시를 중복 생성하지 않는다.
- 공백은 요청하지 않고 입력창에 머문다. 언어 전환은 현재 입력 DOM과 그래프 등급을 보존한다. 검색 실패는 기존 오류 UI를 사용하고 결과 카드·즐겨찾기·상세 이동·뒤로 가기도 기존 기능을 재사용한다. 검색어를 URL이나 별도 영구 저장소에 추가하지 않았다.

## 운영 후속 조치 — 실행하지 않음

현재 로컬 `graph-snapshots.yml`은 시간당 실행 기회에 기존 D+1/3/7/14 및 이후 주간 정책을 적용한다. **모든 조건을 매일 수집하는 설정이 아니다.** `daily-snapshots.yml`도 수동 실행·아티팩트 보존 방식이다. 이번 작업에서 cron·쓰기 권한·변수·자동 커밋·푸시·배포를 변경하거나 실행하지 않았다.

기존 graph 수집 흐름은 이제 `원본 수집/검증 → 파생 평균 생성 → 기존 영구 원본 보존 → 빌드에서 재검증/파생 → Pages`로 연결된다. 기존 전용 데이터 브랜치가 원본을 영구 보존하므로 새 배포에서도 과거 평균을 재생성할 수 있다. 로컬 원본 보존 기간을 줄이는 경우에도 파생 평균은 기존 파일과 병합한다.

실제 운영은 사용자 승인 후 다음을 점검해야 한다.

1. 저장소 Actions 변수 `HOW_GRAPH_ARCHIVE_ENABLED`와 `HOW_GRAPH_PUBLIC_URL` 값을 인증된 계정으로 확인한다. 현재 변수 값을 안다고 가정하지 않는다.
2. `HOW_GRAPH_PUBLIC_URL`은 실제 Pages의 `/HOW/data/snapshots/` HTTPS 디렉터리여야 한다. 검증된 통계 패치가 없다면 `HOW_GRAPH_PATCH_ID`를 임의 지정하지 않는다.
3. 기존 영구 브랜치 존재 여부를 확인하고, 최초 승인 실행에만 기존 workflow_dispatch의 bootstrap을 사용한다. 새 별도 수집기나 병렬 스케줄을 추가하지 않는다.
4. 매일 3지역 9원본을 반드시 얻고 싶다면 기존 주간 정책과 요청 예산을 변경해야 한다. 기본 예상은 통계 API 최대 27회/수집일이며 합성은 로컬 계산이다. 이는 별도 검토·승인이 필요한 변경안으로 남겼다.
5. 승인된 게시 이후 공개 원본 인덱스와 역할 평균 파일의 최신 시각을 함께 확인한다. 로컬 수집 성공을 원격 게시 성공으로 간주하지 않는다.

## 검증 및 변경 파일

- 전체 테스트 **368/368 통과**, 기존 363개 유지＋5개 추가. 최종 차트 DOM 수정 후 관련 26개도 다시 통과했다.
- 빌드 성공: 663개 다국어 정적 진입점. Pages `/HOW/` 검증 성공, 로컬 에셋 18개. 기존 500kB JS 번들 경고는 유지된다.
- 실제 Chrome: 320·390·430·1366·1440·1920px × 한국어·영어·일본어 18조합. 그래프 독립 조건·고정 색상·툴팁·검색어 전달·검색 결과→상세→뒤로 가기를 검사했다. 그래프 등급·기간 변경은 OverFast 통계 API 추가 요청이 없었다.
- 실제 관측 데이터는 이번에 OverFast에서 수집한 원본과 기존 저장 원본이다. 브라우저의 플레이어 검색은 기존에 저장한 실제 공개 TeKrop 응답을 재생했다. 신규 실시간 플레이어 API 검색 성공으로 보고하지 않는다.
- 모션 별도 검사: 390·1440px에서 시작·중간·종료 애니메이션과 언어 전환 후 검색어·그래프 선택 유지 확인. 일반 화면 검사는 Reduced Motion으로 진행했다.
